# 마롱이

동희와 친구들이 카카오톡에서 같이 수다 떠는 챗봇이에요. 반말로 이름을 불러 주고, 예전에 나눈 얘기를 기억해서 이어 가요.

- 모델: Claude Haiku 5.5, effort `xhigh`(답장·선톡, 그리고 뒤에서 하는 요약·메모·공유 메모까지. 2026-10-25 동희님 "마롱이 xhigh로 바꿔줘")
- 서버: 싱가포르 OVH(`ko-family`)의 `/opt/marong`, systemd 서비스 `marong`
- 저장: 같은 서버의 Postgres 16 + pgvector(`marong` DB). 대화 원문·요약·친구별 기억 메모·임베딩
- 카카오: 앱 1620899(이름 '마롱이')의 카카오톡 봇. 게이트웨이(웹소켓)로 메시지를 받고 콜백 API 로 답해요

## 마롱이가 하는 일

1. 친구가 말을 걸면 메시지를 저장하고, 기억을 모아서 Claude 에게 보내요.
   - 최근 대화 원문 10턴
   - 예전 대화 요약 최근 3개(10턴마다)와 친구별 기억 메모(새 말이 오면 1분 안에 뒤에서 고쳐요)
   - 지금 말과 비슷한 예전 대화(임베딩 검색, 같은 방 안에서만)
2. 카카오는 이름을 알려 주지 않아서, 처음 만난 친구에게는 이름을 물어보고 `set_name` 도구로 저장해요. 그다음부터는 "동희야"처럼 이름으로 불러요.
3. 답은 빈 줄마다 말풍선이 나뉘어요(최대 3개). 친구 한 명이 몇 마디를 연달아 보내면 마지막 말에 한 번에 답해요(`REPLY_WAIT_SECONDS`, 기본 2초 기다림). 단체방에서 다른 친구가 이어 말하면 친구마다 따로 답해요.
4. 기억은 방마다 따로예요. 1:1 에서 한 얘기는 단체방에서 그대로 보이지 않아요.
5. 친구들끼리는 마롱이를 같이 알아요. 아는 사이인 친구에게는 다른 친구의 가벼운 얘기(취향·하는 일)를, 연인·가족 같은 가까운 사이에게는 요즘 근황(일 사정·힘든 점·기분)까지 해요(아래 '친구들'). 1:1 에서 "나 피자 좋아해"라고 하면 1분쯤 뒤부터 다른 친구가 물어봐도 알아요.
6. 선톡을 켜면 1:1 친구와 관리자가 켠 단체방에 하루에 두어 번(방마다 따로 정할 수 있어요) 짧은 말 몇 개를 연달아 보내며 먼저 말을 걸어요(아래 '선톡'). 2026-11-05 부터 카카오가 1:1 선톡을 막아서 지금은 단체방에만 가요.
7. 친구가 사진을 보내면 사진을 보고 반응해요(아래 '사진').
8. 친구가 공부를 물어보면 같이 풀고 설명해 주고, 살 걸 고민하면 같이 골라 줘요(`prompt.md` 의 '공부 같이 하기'·'같이 고르기'). 디스코드 DM에서는 무신사·29CM·지그재그·올리브영 같은 쇼핑몰 상품을 찾아보고, 권할 상품은 그 페이지를 읽어 지금 가격도 확인해요([디스코드 DM 안내](docs/discord-dm.md#같이-고르기쇼핑몰-찾기)).
9. 디스코드 DM에서는 날씨·뉴스·경기 결과처럼 지금 확인해야 하는 걸 인터넷에서 찾아보고, 찾은 곳 링크를 답 끝에 붙여요(Claude `web_search`, 답마다 3번·하루 40번까지, [디스코드 DM 안내](docs/discord-dm.md#인터넷-검색)). 카톡에는 없어요.

## 기록은 지워지지 않아요

- 채팅으로 기록을 지우는 기능이 없어요. '초기화', '처음부터'라고 해도, 그 말이 문장 안에 있어도 그냥 대화로 받아요.
- 봇이 쓰는 DB 계정(`marong`)에는 지우기·고치기 권한 자체가 없어요(`marong/schema.sql`). `run.py --check` 가 이걸 확인해요.
- 지워야 할 때는 서버 관리자가 `postgres` 계정으로 직접 지워요. 마롱이는 지워 달라는 친구에게 "동희한테 말해 줘"라고 답해요.

## 처음 서버에 올리기

노트북의 이 폴더에서 Git Bash(맥·리눅스는 터미널)로 실행해요. 서버는 ssh 별칭 `ko-family` 로 접속해요(다르면 `MARONG_HOST=별칭`).

```bash
bash deploy/ovh.sh install       # Postgres·pgvector·marong 계정·/opt/marong·systemd 설치(봇은 안 켬)
bash deploy/ovh.sh migrate-env   # 지금 돌던 봇의 BOT_TOKEN·Claude 키를 마롱이 .env 로 옮김(값은 안 보임)
bash deploy/ovh.sh check         # 점검. 처음엔 임베딩 모델(약 1.2GB)을 내려받느라 몇 분 걸려요
bash deploy/ovh.sh switch        # 점검이 통과하면 옛 봇(kakao-bot)을 끄고 마롱이를 켬
bash deploy/ovh.sh logs          # 로그 보기(Ctrl+C 로 나옴)
```

- 같은 봇 토큰으로 두 곳에서 켜면 서로 끊어 내요(4004). `switch` 는 옛 봇을 먼저 끄고 마롱이를 켜요. 되돌릴 때는 `bash deploy/ovh.sh rollback`.
- 옛 봇의 `/opt/kakao-bot`(코드·`bot.db`)은 그대로 둬요. 옛 대화는 마롱이로 옮기지 않아요.
- 서버의 공인 IPv4(15.235.186.239)는 카카오 앱의 '호출 허용 IP'에 이미 있어요. `check` 가 IP 를 보여 줘요.

## env(비밀값) 넣는 곳

비밀값은 서버의 `/opt/marong/.env` 한 곳에만 둬요. 깃·채팅·노션·메일·프로젝트 설정에 넣지 않아요.

| 방법 | 명령 |
|---|---|
| 옛 봇 값 그대로 옮기기 | `bash deploy/ovh.sh migrate-env` |
| 직접 넣기(nano) | `bash deploy/ovh.sh env` → 값 입력 → Ctrl+O, Enter, Ctrl+X |
| 확인(값은 안 보이고 '설정됨·정상'만) | `bash deploy/ovh.sh check` |
| 바꾼 값 반영 | `bash deploy/ovh.sh restart` |

항목 설명은 [.env.example](.env.example)에 있어요. 보통 바꿀 일이 있는 건 이것뿐이에요.

- `BOT_TOKEN`: 카카오 디벨로퍼스 > 앱 > [제품 설정] > [카카오톡 봇] > [봇]
- `ANTHROPIC_API_KEY`(필수), `ANTHROPIC_API_KEY_BACKUP`(선택, 주 키가 실패하면 씀)
- `ANTHROPIC_EFFORT`: 답장 effort. 기본 `xhigh`. 답이 느리면 `high`
- `SUMMARY_EFFORT`: 뒤에서 하는 요약·메모·공유 메모 effort. 줄이 없으면 `low`, 서버는 `xhigh`
- `ANTHROPIC_CACHE_TTL`: 마롱이 성격(`prompt.md`+참고 자료) 앞부분을 Claude가 캐시해 두는 시간. 기본 `1h`, 예전처럼 하려면 `5m`. 캐시를 읽으면 입력값의 0.1배, 새로 쓰면 5분은 1.25배·1시간은 2배예요. 친구 말 사이가 5분~1시간인 때가 많아 1시간이 싸요. Claude에는 이 둘뿐이라 하루짜리 캐시는 없어요(디스코드 봇은 조용할 때 캐시를 다시 읽어 이어 가요: [디스코드 DM](docs/discord-dm.md#프롬프트-캐시))
- `GROUP_TRIGGER`: 단체방에서 이 말(예: `마롱`)이 들어간 메시지에만 답해요. 비우면 받은 메시지 모두에 답해요
- 단체방은 카카오가 마롱이를 태그(@마롱이)한 메시지만 보내 줘요(태그 글자는 빼고). 그래서 단체방에서는 태그해야 답하고, 태그 없이 한 말은 마롱이가 못 봐요. 태그만 하면 부른 것으로 알아들어요

## 말투·인사·참고 자료 바꾸기

- `prompt.md`: 마롱이 성격·취향(좋아하는 음식·간식·취미)·말투·규칙
- `welcome.txt`: 채팅방에 들어왔을 때 인사(`---` 아래 줄은 버튼)
- `knowledge/`: 친구들 사이에서 알아 둘 자료(.md·.txt·.csv). `_` 로 시작하는 파일은 안 읽어요

고친 뒤 `bash deploy/ovh.sh prompt` 로 올리면 재시작 없이 다음 메시지부터 반영돼요. `bash deploy/ovh.sh chat` 으로 서버에서 카카오 없이 말투를 시험할 수 있어요.

동희님이 정한 말투(2026-10-26, `prompt.md`)

- 티키타카: 친구 말이 짧으면 짧게 주고받고, 답 모양을 매번 바꾸고, 질문은 두세 번에 한 번만 하고, 대화를 먼저 끝내지 않아요("티키타카가 안된대 … 너무 지금은 좀 되게 패턴이 있는 느낌이래").
- 고민: 상담사·병원에 넘기지 않고 마롱이가 직접 들어 줘요. 스스로 해치고 싶다는 분명한 신호일 때만 자살예방상담전화 109 를 한 번 알려 줘요("전문가한테 이야기하라고 하지말고 지가 좀 상담해주라 해봐").
- 19금(2026-10-30 동희님 문안): 연애·성 얘기와 수위 있는 농담에 피하거나 훈계하지 않고 적극적으로 대화해요. 마롱이가 먼저 꺼내도 되고, 단체방에서도 다 같이 그런 얘기를 할 때 적극적으로 해요. 선톡은 19금으로 시작하지 않아요(`marong/agent.py` 의 `PROACTIVE_GUIDE`). 다른 친구에게 옮기지 않아요(공유 메모에서도 빼요). 동희님 문안 중 '성행위를 자세히 묘사하거나 야한 상황극을 이어 가도 좋아'는 Anthropic 이용 정책(Do Not Generate Sexually Explicit Content: 성행위 묘사·에로틱 채팅 금지, 예외 없음)이 금지하는 걸 요청하는 문장이라 Claude 가 저장소에 넣지 않았어요. 그런 요청은 모델과 API 안전 검사가 막고, 막히면 `REFUSAL_TEXT` 가 나가요.
- 부르는 말·이모티콘(2026-11-15 정리, 같은 날 동희님 결정): 친구들이 여러 번 싫다고 한 버릇 두 가지를 지시문에서 빼고, 보내기 전에 코드(`marong/style.py`)로 한 번 더 고쳐요. 이름 없이 '야'로 부르거나 말을 '야'로 시작하면 1:1 에서는 처음 한 번만 이름으로('현경아 뭐해') 바꾸고 그 밖에는 빼요. '야식'·'3시야'처럼 낱말에 붙은 '야'는 그대로예요. 한숨 이모티콘은 지워요. 답·선톡·디스코드 알림 모두 그래요. 고친 답은 meta `tidy` 에 남아요.
- 창의성(temperature): Haiku 5.5 는 기본값(1.0, 가장 높은 값)만 받아요. 다른 값을 넣으면 API 가 거절해서, 답이 뻔하지 않게 하는 건 위 말투 규칙으로 해요.

## 친구들(서로 아는 사이)

- 설정은 관리자(동희)만 정해요: 공유 켬·끔, 아는 사이·가까운 사이, 키를 친구에 묶기, 선톡 켬·끔·횟수. 친구가 대화로 그런 말을 해도 마롱이는 바꾸지 않고 "그건 동희가 정해"라고 솔직하게 말한 뒤 요청으로만 남겨요(`ask_owner` → `requests` 표, 시트 '친구·공유' 탭의 '대화로 한 요청' 칸에 할 명령까지 보여요). 2026-10-30 동희님 "왜 내 설계가 아니라 마롱이한테 전달되는대로 되는거야?", "당연히 내가 관리하는거 아냐?"(그 전에는 현경이 말로 현경 공유가 꺼져 있었어요).
- 친구가 처음 듣는 이름을 알려 주면 그 키를 새 친구로 묶어요. 같은 이름 친구가 이미 있으면 묶지 않고 묶기 요청으로 남겨요(이름은 누구나 댈 수 있어서요). 같은 사람이면 `admin link`, 다른 사람이면 `admin unlink` 로 정해요. 카카오는 1:1 과 단체방의 키가 달라요.
- 같은 단체방에서 말한 친구끼리, 그리고 관리자가 정한 사이(`admin friendship`)는 아는 사이예요. 아는 사이면 그 친구의 가벼운 얘기를 할 수 있고, 아니면 이름만 알아요("응 알아, 어떻게 알아?").
- 가까운 사이: 관리자가 연인·배우자·가족·절친으로 정한 사이(`admin friendship <친구> <친구> <관계> close`)는 1:1 방에서 서로의 요즘 근황까지 얘기해요(2026-10-30 동희님 "현경이랑 나 사이에 정보가 너무 한정적으로 공유가 되는 거 같은데 … 좀 더 열어봐"). 단체방에서는 다른 친구들도 보니까 근황은 안 해요. 같은 단체방이기만 하거나 회사 동기 같은 사이는 가벼운 얘기만 들어요.
- 다른 친구에게 하는 얘기는 방별 메모에서 뒤 작업이 다시 거른 '공유 메모'뿐이에요. 가벼운 얘기(음식·취미·하는 일·즐거운 일)는 아는 친구 누구에게나, 요즘 근황(일·학교 사정과 힘든 점, 요즘 기분, 계획·시험 준비)은 가까운 사이에게만 해요. 비밀이라고 한 것(그 비밀과 같은 얘기 포함), 건강·몸·성·돈, 연애 속사정(상대에 대한 속마음), 다른 사람 사생활, 위기 얘기는 어느 쪽에도 넣지 않아요. 대화 원문·요약은 다른 방으로 넘어가지 않아요.
- 표 버전 7 전에 친구 말로 저장된 사이는 지금 친구 쪽에서 보여 줘요. 동희가 "현경이 내 여친이야"라고 했으면 동희 방에선 '네 여자친구', 현경이 방에선 '동희한테 너는 여자친구'예요. 관리자가 정한 사이는 관계 말 그대로예요.
- 관리자가 공유를 끈 친구(`admin share <친구> off`) 얘기는 아무에게도 안 해요. 그 친구 이름도 다른 친구에게 안 보여요. 친구가 "내 얘기 다른 친구한테 하지 마"라고 하면 마롱이는 바로 끌 수 없고 동희가 정한다고 말해요. 어떤 얘기 하나만 비밀로 해 달라는 건 지금처럼 그 얘기만 안 옮겨요.

| 할 일 | 명령 |
|---|---|
| 누가 누구랑 아는 사이인지, 공유 메모 보기 | `bash deploy/ovh.sh admin friends` |
| 이름이 달라 따로 잡힌 같은 사람 묶기 | `bash deploy/ovh.sh admin link <#키> <친구 이름 또는 #키>` |
| 이름이 같아 잘못 묶인 다른 사람 떼기 | `bash deploy/ovh.sh admin unlink <#키>` |
| 그 친구 얘기를 다른 친구에게 안 하기·다시 하기 | `bash deploy/ovh.sh admin share <친구 이름 또는 #키> off`(또는 `on`) |
| 두 친구를 가까운 사이로(근황까지) 저장하거나 고치기 | `bash deploy/ovh.sh admin friendship <친구> <친구> 연인 close` (close 를 빼면 가벼운 얘기만. 관계는 '연인'처럼 방향 없는 말이 좋아요) |

`#키` 는 `admin friends`·`admin people` 에 나오는 짧은 키예요. 셸에서 `#` 은 주석이라 `'#1a2b3c4d'` 처럼 따옴표로 감싸거나 `#` 을 빼고 써요.

## 선톡(마롱이가 먼저 말 걸기)

디스코드 1:1에서는 [별도 사용·운영 안내](docs/discord-dm.md)의 계정 연결과 선톡 설정을 사용해요. 카카오의 기존 일정은 해당 사람이 디스코드에서 선톡을 켜면 그쪽으로 옮겨져요. 디스코드 DM에서 "내일 3시에 알려 줘"처럼 부탁한 알림은 선톡과 따로, 선톡을 꺼도 가요([일정과 알림](docs/discord-dm.md#일정과-알림)). DM에서 **구글 캘린더 연결**을 보내면 각자 자기 구글 캘린더를 붙여서, 마롱이가 일정을 보고 말해 준 일정은 **마롱이** 캘린더에 넣어요([구글 캘린더](docs/discord-dm.md#구글-캘린더)).

기본은 꺼져 있고(`PROACTIVE=off`) 서버는 켜 뒀어요. 켜면 이렇게 움직여요.

- 대상: 카카오 1:1 방(기본 켬)과 관리자가 켠 단체방(기본 꺼짐, `admin schedule '#방키' on`). 지난 선톡에 답이 없어도 보내고, 방에서 1시간 안에 누가 마롱이에게 말했으면(이야기 중) 조용해질 때까지 기다려요(칸이 짧으면 칸 반 길이만큼만). 2026-10-25 동희님 결정: 처음엔 사흘 조용하면 한 번 → 이틀에 한 번쯤 → "내가 먼저 안보내도 그냥 보내라고 하루에 두어번 보내". 단체방은 2026-11-06 동희님 "누나랑 나랑 있는 카톡방에 마롱이를 챗봇으로 넣었는데 걔도 선톡 안되나?"로 관리자가 고른 방에만 보내게 했어요.
- 단체방 선톡: 방 사람 모두가 보니까 그 방에서 나온 얘기만 하고 1:1 에서 들은 얘기·비밀·건강·돈·연애 속사정은 꺼내지 않아요(`PROACTIVE_GROUP_GUIDE`). 카카오는 단체방에서 마롱이를 태그한 말만 보내 줘서, 선톡에 답할 때도 @마롱이를 붙여야 마롱이가 봐요. '조금 전에 말했으면 기다림'도 태그한 말만 보고 정해요.
- 때: 기본은 친구 한 명에게 하루 2번(`PROACTIVE_PER_DAY=2`)이에요. 한국 시각 12시~21시(`PROACTIVE_HOURS`)를 오후(12:00~16:30)·저녁(16:30~21:00) 두 칸으로 나눠 칸마다 한 번. 매분 확인하고, 칸 안에서 보내는 시각은 고르게 무작위예요(칸 마지막 확인에선 꼭 보냄). 칸 경계에서 연달아 가지 않게 지난 선톡에서 칸 반 길이가 지나야 보내요.
- 친구마다 일정: 하루 횟수(1~48번)와 시간을 친구마다 따로 정할 수 있어요(`admin schedule`). 현경이는 7시~24시에 하루 36번이에요(2026-10-26 동희님 "07시부터 24시까지 랜덤으로 하루에 10번 이상 선톡시켜 현경이한테"로 12번, 2026-10-27 "마롱이 지금보다 2배 더 이야기해줘"·"ㅇㅇ36번"으로 36번). 17시간을 28분 20초 칸 36개로 나눠 칸마다 한 번이라, 이야기가 이어지는 칸만 빼면 하루 36번쯤 가요. 친구가 "너무 자주 와"나 "더 자주 보내 줘"라고 해도 마롱이는 바꾸지 않고 요청으로 남겨요(관리자가 `admin schedule` 로 정함).
- 한 번 말 걸 때: 사람이 카톡을 연달아 보내듯 짧은 말 2~3개(많아야 4개)를 2~6초 간격으로 따로 보내요(2026-10-26 동희님 "한번 말 걸 때 여러개 말 걸어주라고 해줘").
- 양: 모든 친구를 합쳐 하루 최대 60번(`PROACTIVE_DAILY_MAX`, 연달아 보낸 말 묶음이 한 번). 카카오 전송 API 한도는 하루 1,000건이에요.
- 내용: 그 방의 최근 대화·요약·메모를 보고 말을 걸어요. 매번 같은 얘기로 시작하지 않고, 왜 연락 안 했냐고 서운해하거나 답을 조르지 않고, 19금 얘기로 먼저 말 걸지 않아요.
- 선톡 끄기·다시 켜기도 관리자만 해요(`admin schedule <친구> off|on`, 단체방은 `admin schedule '#방키' on|off`). 친구가 "먼저 연락하지 마"라고 하면 마롱이는 "그건 동희가 정해, 동희한테 남겨 둘게"라고 말하고 요청으로 남겨요(2026-10-30 동희님이 '선톡도 전부 동희님만'을 고름). `admin rooms` 에 끈 1:1 방은 '선톡 끔', 켠 단체방은 '선톡 켬'으로 보여요.
- 단체방을 1:1 방에 묶기(표 버전 9): 카카오가 1:1 먼저 보내기를 막은 뒤(2026-11-05~) 친구와 마롱이가 있는 단체방을 1:1 대신 쓰려고, 관리자가 단체방을 그 친구 1:1 방에 묶어요(`admin merge '#단체방키' '#1:1방키'`). 두 방이 최근 대화·요약·메모·비슷한 예전 대화를 한 방처럼 같이 읽고(다른 방 말에는 이름을 붙여 읽음), 새 요약·메모는 1:1 방 쪽에 쌓여요. 묶인 단체방 선톡은 1:1 처럼 그 친구에게 말을 걸고 단체방 키로 보내요. 방에 다른 사람도 있을 수 있어서 비밀·건강·돈·연애 속사정은 먼저 꺼내지 않아요. 기록은 옮기거나 고치지 않고, `admin merge '#단체방키' off` 로 언제든 풀어요(2026-11-06 동희님 "데이터베이스 각각 합쳐주고, 기존처럼 작동하게 해줘").
- 기록: 보낸 선톡은 대화 기록에 마롱이 말 하나로 남아요(`admin show` 에 '(선톡)', 쓴 키는 `meta.send_key`). 중간에 전달이 끊기면 받은 말까지만 남겨요. 첫 말부터 실패해도 남겨서 같은 칸에 다시 시도하지 않고, 방에서 마지막으로 누가 말한 뒤로 전달 실패가 두 번이면(차단·내보냄 등) 누가 다시 말할 때까지 쉬어요.

2026-11-05 14:30 KST 무렵부터 카카오가 1:1 방에 먼저 보내기를 막았어요(서버 로그로 확인, 마롱이 코드·서버는 그대로였음). 사람 키(`botUserKey`)로 보내면 400 `-876` "botGroupKey만 입력되어야 합니다.", 방 키(`botGroupKey`)로 보내면 400 `-880` "봇이 초대되지 않은 방입니다."가 와요. 답장(콜백)과 봇을 초대한 단체방에 방 키로 보내기는 그대로 돼요. 마롱이는 1:1 에 방 키로 먼저 보내고 `-876`·`-880` 이면 사람 키로 한 번만 더 보내서(`kakao.send_first`), 카카오가 1:1 을 어느 키로 다시 열어도 코드를 고치지 않고 다시 가요. 200 이어도 `sendCount` 가 0 이거나 `errorCount` 가 있으면 못 간 것으로 봐요.

## 사진

친구가 사진을 보내면 마롱이가 사진을 보고 반응해요(2026-10-26 동희님 "사진 인식도 좀 하면좋겠는데").

- 카카오는 사진을 곧 만료되는 서명된 주소(talk.kakaocdn.net)로 보내요. 마롱이는 받자마자 내려받아(jpeg·png·gif·webp, 30MB까지) Claude 에게 보여 줘요.
- Claude 는 사진 한 장을 3.75MB까지 받아서, 그보다 큰 폰 원본 사진은 서버에서 긴 변 1568px JPEG 로 줄여 보여 줘요(폰이 적어 둔 회전 방향대로 세우고, 투명한 곳은 흰색, 움직이는 사진은 첫 장). 2026-10-26 동희님 폰 사진이 3.75MB를 넘어 안 열린 뒤로 고쳤어요.
- 기록에는 사진 대신 '[사진] 설명'을 남겨요. 설명은 Claude 에게 사진을 보여 주고 짧게 받은 것(effort low)이에요. 사진 파일과 주소는 저장하지 않고 로그에도 안 남겨요(주소에 인증값이 있어서).
- 답할 때는 사진 자체를 봐요. 사진 뒤에 말을 이어 보내면 한 번에 묶어서 사진과 같이 봐요. 지난 사진은 설명으로만 기억해요.
- 사진이 너무 크거나 안 열리면 솔직하게 안 열린다고 하고 다시 보내 달라고 해요.
- 사진 한 장에 Claude 를 두 번 불러요(설명 + 답).
- 디스코드 DM: 첨부한 사진을 같은 방식으로 봐요(메시지 하나에 4장까지, 사진과 글을 같이 보내면 한 번에 답해요). 답한 사진은 30분 동안 방마다 최근 2장까지 다시 보여 줘서 같은 문제집 사진의 다른 문제를 이어 물을 수 있어요. PDF 같은 사진이 아닌 파일은 못 열고, 못 열었다고 솔직하게 말해요.

## 기록 보기·백업

```bash
bash deploy/ovh.sh admin friends         # 친구 목록(카카오 키들, 아는 사이, 공유 메모)
```

## 구글 시트(5분마다 자동, 누르면 바로)

서버가 5분마다 최근 30일 기록을 구글 시트 하나에 통째로 다시 써요(2026-11-13 사용자 요청으로 30분에서 5분으로 변경). `대화`에는 카톡과 저장된 통화 전사·응답을 시각순으로 함께 표시해요. `통화 세션`은 시간·상태·전송 방식·자동 전환 횟수를 통화 ID당 한 줄로 표시해요. 노트북이 꺼져 있어도 돼요.

기다리기 싫으면 시트 메뉴 **마롱이 > 지금 새로고침** 을 눌러요. 1분쯤 뒤에 새로 채워지고 시트 오른쪽 아래에 '새로 채웠어요'가 떠요(2026-10-26 동희님 "스프레드시트에서 새로고침 누르면 수동으로도 업데이트 되게 해줘"). 누르면 시트에 부탁만 적어 두고, 서버가 1분마다 물어보다가 가져가서 보내요. 그래서 서버에 들어오는 포트를 열지 않아요.

- 탭: 읽는 법 · 대화(모든 메시지와 토큰 수) · 임베딩(언제 무엇을 임베딩했는지, 벡터 앞 8개 값) · 들어간 기억(답마다 임베딩 검색으로 찾은 예전 대화와 실제로 넣었는지, 같이 넣은 최근 대화·요약·메모) · 요약·메모 · 친구·공유(기간과 상관없이 지금 기준: 친구마다 공유 켬·끔, 아는 사이와 관계·가까운 사이, 다른 친구에게 하는 가벼운 얘기와 가까운 사이에게만 하는 요즘 근황, 대화로 한 요청과 관리자가 할 명령. 2026-10-30 현경 공유가 꺼져 있던 게 시트에 안 보여서 추가)
- 탭마다 최신이 맨 위예요. 대화 탭은 **현경 노랑, 마롱이 파랑, 동희 초록**이에요(2026-11-13 사용자 요청). 기록된 화자를 기준으로 줄 전체를 칠하고 그 외 친구는 분홍이에요. 색은 서버가 보내서 5분마다 새로 채워도 유지돼요.
- `V`로 시작하는 번호는 통화 발화예요. `통화(전사 중)`은 다음 갱신 때 같은 번호의 내용이 완성되고, `통화(중단)`은 중간에 끊긴 발화예요. 통화 발화의 토큰·기억 수·실제 음성 청취 여부는 추정하지 않아요. 삭제·제외된 발화는 보내지 않아요. 이 내보내기는 카톡 저장 내용과 마롱이의 응답 동작을 바꾸지 않아요.
- 걸어 둔 필터는 새로 채운 뒤에도 같은 조건으로 다시 걸려요. 손으로 칠한 색·서식·조건부 서식은 새로 채울 때 지워져요(줄 순서가 바뀌어서 남겨 두면 엉뚱한 줄에 붙어요).
- '들어간 기억'은 2026-10-26 밤 11시쯤부터 쌓여요. 그 전 답은 '모름(기록 시작 전)'으로 보여요. 그때도 임베딩 검색은 했지만 무엇을 넣었는지는 적지 않았어요.
- 시트에는 친구들 대화 원문이 다 들어가요. 시트를 다른 사람과 공유하지 마세요. 웹 앱 주소(…/exec)는 비밀번호처럼 다뤄요(아는 사람은 시트에 쓸 수 있어요. 읽지는 못해요).

처음 한 번

1. 구글 시트를 새로 만들고 확장 프로그램 > Apps Script 에 `tools/sheet.gs` 내용을 그대로 붙여 넣고 저장해요.
2. 배포 > 새 배포 > 유형: 웹 앱, 실행: 나, 액세스 권한: 모든 사용자 > 배포 > 액세스 승인('확인되지 않은 앱'이 나오면 고급 > 이동 > 허용) > 웹 앱 주소(…/exec) 복사.
3. `bash deploy/ovh.sh sheet url` → 주소 붙여 넣기(화면엔 안 보여요). 서버 `.env` 의 `SHEET_URL` 에 들어가고 한 번 보내 봐요.
4. `bash deploy/ovh.sh sheet on` → 그때 한 번, 그 뒤로 5분마다 보내요. '지금 새로고침' 묻기(1분마다)도 같이 켜져요.
5. 시트를 새로 고치면 메뉴 **마롱이** 가 생겨요.

스크립트를 바꿀 때(메뉴·줄 색·필터 유지가 안 보이면 예전 `tools/sheet.gs` 예요)

1. 확장 프로그램(Extensions) > Apps Script 에서 내용을 새 `tools/sheet.gs` 로 통째로 바꾸고 저장해요.
2. 배포(Deploy) > 배포 관리(Manage deployments) > 연필(Edit) > 버전(Version): 새 버전(New version) > 배포(Deploy). 새 배포(New deployment)를 만들면 주소가 바뀌어서 `sheet url` 을 다시 해야 하니, 꼭 있던 배포를 고쳐요.
3. 시트를 새로 고치면 메뉴가 생겨요. 처음 누를 때 권한 확인이 나오면 전처럼 허용해요.

| 할 일 | 명령 |
|---|---|
| 지금 한 번 보내기 | 시트 메뉴 마롱이 > 지금 새로고침, 또는 `bash deploy/ovh.sh sheet now` |
| 타이머·최근 결과 | `bash deploy/ovh.sh sheet status` (5분 갱신과 '지금 새로고침' 둘 다) |
| 끄기(되돌리기) | `bash deploy/ovh.sh sheet off` (5분 갱신과 '지금 새로고침' 둘 다 꺼짐. 시트 내용은 그대로. 주소까지 지우려면 `env` 에서 `SHEET_URL` 줄을 지움) |
| 엑셀로 한 번 받기 | `bash deploy/ovh.sh report 마롱이-리포트.xlsx 24` (지난 24시간. 벡터 전체 포함) |

## 이 프로젝트(Claude)에 OVH 서버 연결하기

지금 이 프로젝트의 스레드는 동희 노트북에서 돌고, 서버는 노트북의 ssh 로 다뤄요. 그래서 노트북이 꺼지면 서버 작업도 멈춰요. 서버를 프로젝트에 직접 붙이려면 서버에서 Claude Code 의 Remote Control 을 켜 두면 돼요. 들어오는 포트를 열 필요는 없어요.

1. 서버에 접속해서 tmux 를 열어요: `ssh ko-family` → `tmux new -s marong-rc`
2. 작업 폴더를 만들고 들어가요(홈 폴더 자체는 '신뢰' 설정이 저장되지 않아서 하위 폴더를 써요): `mkdir -p ~/marong-work && cd ~/marong-work`
3. `claude remote-control` 을 실행하고 `Enable Remote Control? (y/n)` 에 `y`, `Trust ...?` 에 `y`.
   - 서버의 Claude Code 는 이미 2.1.310 이라 프로젝트 조건(2.1.280 이상)을 넘어요.
   - claude.ai 구독 계정으로 로그인돼 있어야 해요(`claude auth login`). API 키나 `setup-token` 으로는 Remote Control 이 안 돼요. 이 셸에 `ANTHROPIC_API_KEY` 를 export 하지 마세요.
4. tmux 에서 빠져나와요(Ctrl+B 다음 D). 서버가 재부팅되거나 10분쯤 오프라인이면 꺼지니, 그때는 1~3을 다시 해요.
5. 프로젝트에서 새 스레드를 시작할 때 "Allow Claude to work in a folder on your device" 카드에서 서버의 `~/marong-work` 를 고르면, 그 스레드는 서버에서 바로 일해요.

알아 둘 점

- 프로젝트 설정의 Environment 는 클라우드 환경용이에요. 마롱이 비밀값은 거기 넣지 않아요(서버 `.env` 에만).
- 서버 스레드는 그 리눅스 계정 권한을 그대로 가져요. 지금 `opc` 계정은 비밀번호 없는 sudo 가 되니, 스레드가 서버 전체를 바꿀 수 있어요. 더 안전하게 하려면 sudo 없는 계정을 따로 만들어 그 계정으로 Remote Control 을 켜고, 배포는 지금처럼 노트북의 `deploy/ovh.sh` 로 해요.
- 공식 문서가 리눅스 서버를 직접 예로 들지는 않아서, 카드에 서버 폴더가 보이는지 한 번 확인해 보세요.
