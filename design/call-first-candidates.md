## 그린 방법

통화 화면(`tools/vertex_live/static/index.html`, `style.css`)과 글 대화 화면(`marong/app_chat_static/index.html`, `chat.css`)을 스크립트 없이 브라우저(Playwright Chromium)에 띄우고, 목업 CSS와 예시 상태를 얹어 찍었어요. 그래서 글꼴·여백·색은 지금 화면 그대로예요. 벨 화면(앱의 `RingActivity`)은 웹이 아니라서 `activity_ring.xml`의 값으로 HTML을 따로 그렸어요. 실제 앱이 그린 화면은 아니에요.

- 예시 그림 두 장(털모자, 닭꼬치)은 설계 전에 만든 시제품(프로젝트 파일 `marong-topic-pictures-20261116/`)을 512px WebP로 줄인 것이에요. 실제 그림 세트는 따로 만들어요(SPEC-282).
- 예시 글은 화면을 보이려고 지은 것이고 실제 대화가 아니에요.

## 추천

**통화 A + 글 대화 A.**

- 통화 B는 가장 작은 폭에서 통화 단추를 가려서 08 정의를 어겨요. 카드를 줄이면 그림이 너무 작아져요(160px보다 작게).
- 글 대화 A는 익숙한 모양이고, 기다리는 칸과 못 받은 상태를 칸 하나로 다뤄서 단순해요.
- 반론: 통화 A는 15초 동안 마롱이 표정이 안 보여요. 그림 자체가 마롱이 모습이고 15초 뒤 저절로 돌아오므로 괜찮다고 봤어요(추정, 12단계 시험에서 확인).
- A를 쓰려면 그림 세트가 주인공을 가운데 원 안에 그려야 해요(원으로 잘려도 보이게). 기능 명세 5.3(AI-22)의 그림체 지시에 더했어요.

## 토큰

넣은 것(`base.tokens.json`): `size.topic-picture` 240px. 글 대화의 그림과 기다리는 동안의 빈 칸이에요.

쓰는 기존 토큰: `size.face-call`(248px, 통화 A의 그림 원), `size.touch-min`(48px, 그림 닫기), `space.xs`·`space.md`·`space.lg`(4·16·24px), `radius.md`·`radius.full`(16·999px), `font-size.caption`(13px)과 `font-weight.bold`(700, 제목 칩), 색은 `color.a`·`color.b`의 `surface`, `surface-2`(화면 CSS의 `--raised`), `text`, `line`. 그림자는 두 화면 CSS의 `--panel-shadow`를 그대로 써요(토큰 없음, 지금 화면과 같음).

B의 값은 토큰에 넣지 않았어요. 08 정의의 '그림 닫기 44px'은 `size.touch-min`(48px)으로 맞췄어요.

## 확인한 것과 못 한 것

- 확인함(2026-11-16 23:58 KST에 찍음): 27장(360×740 17장, 430×932 10장), 페이지 오류 0, 가로 넘침 0. 목업 페이지에 쓴 23장의 파일이 모두 있음.
- 대비(WCAG 2.2 상대 휘도 식, 위 토큰 값으로 계산): 제목 칩 글씨와 닫기 X 표시는 11.7:1(밤)·12.75:1(낮). 낮 테마에서 닫기 단추 바탕과 흰 그림은 1.23:1이라 단추는 X 표시와 그림자로 알아봐요. 기다리는 칸과 화면 바탕은 1.35:1(밤)·1.15:1(낮)이고 장식이라 화면 읽기 프로그램에는 숨겨요.
- 찾은 것: 벨 화면의 긴 미리보기 줄 "나 오늘 처음으로 눈사람 만들어 봤는데 진짜 귀여워!"가 360px에서 '봤는/데'처럼 단어 중간에서 끊겨요(브라우저 기본 줄바꿈으로 그린 것). 그래서 그림 세트의 미리보기 한 줄은 벨 화면 한 줄에 들어가게 16자 안팎으로 지어요(기능 명세 3.1에 더함). 앱에서 어절 단위로 끊는 설정은 11단계에서 실제 기기로 확인해요.
- 확인하지 않음: 실제 휴대폰의 앱 창, 실제 앱이 그린 벨 화면, 15초 뒤 사라지는 움직임과 움직임 줄이기, 화면 읽기 프로그램. 11\~12단계에서 실제 화면으로 재요.
