범위 밖: 티켓 판매와 결제, 친구가 자기 한도를 직접 바꾸기, 한도를 넘기 전 미리 알림(푸시), 지난날 사용량 그래프, 전체 합계 한도를 사람별로 나누기.

## 4. 컨텍스트 표

### 사용량 맥락의 바뀐 뒤 전체(CTX-029)

목적: 사람마다 하루에 쓴 양을 세고, 그 사람의 유효 한도가 있을 때만 막고, 친구가 자기 사용량과 한도를 보게 해요.

| Given by | Read model | Command | Aggregate | Events |
| --- | --- | --- | --- | --- |
| 정책: 이 기능이 들어갈 때(한 번) | 프로필이 있는 계정 | 무제한으로 정하기 | 계정 한도 | 계정 한도가 무제한으로 정해짐 |
| 정책: 가입하거나 기존 계정을 이을 때 | | 기본으로 정하기 | 계정 한도 | 계정 한도가 기본으로 정해짐 |
| 관리자 | 회원 목록의 계정 한도·유효 한도·오늘 사용량·이번 달 통화 비용, 기본 한도 | 계정 한도 바꾸기(무제한, 기본, 직접 숫자) | 계정 한도 | 계정 한도 바뀜 |
| 정책: 글 답·통화·그림·검색·쇼핑 읽기가 끝날 때 | | 하루 사용량 더하기(유효 하루 한도가 있으면 넘은 만큼 티켓 빼기) | 하루 사용량, 티켓 | 하루 사용량 더해짐, 티켓 씀 |
| 정책: 글 보내기와 통화 시작 전에 | 유효 하루 한도, 오늘 사용 단위(TERM-191), 티켓 잔액 | 하루 한도 확인하기 | 하루 사용량, 티켓 | 통과함, 또는 한도로 막힘 |
| 친구 | 내 사용량(자기 것만) | | | |
| 관리자 | 회원 목록 | 티켓 넣기(1\~1000) | 티켓 | 티켓 넣어짐 |

- Aggregate rules:
  - 계정 한도의 상태는 셋이에요. 무제한(그 사람에게 사람별 한도가 없음), 기본(기본 한도를 따름), 직접(하루 사용 단위와 통화 월 달러 가운데 정한 것은 그 숫자, 비운 것은 기본 한도를 따름). `[확실]` D106, `[추측]` 상태 이름
  - 유효 한도: 무제한이면 하루와 통화 월 모두 없음. 아니면 하루 = 계정 숫자가 있으면 그 숫자, 없으면 `MARONG_DAILY_UNITS`. 통화 월 = 계정 숫자가 있으면 그 숫자, 없으면 `MARONG_CALL_PERSON_MONTHLY_USD`. 둘 다 없으면 그 한도는 없음이에요. `[추론]`
  - 유효 한도가 없으면 그 한도로는 아무것도 막지 않고 티켓도 빠지지 않아요. 세기는 늘 해요(REQ-480). `[확실]` D106, 기존 SPEC-394
  - 무제한도 서버 전체 장치(통화 전체 예산, 그림 예산, 전체 합계 한도, 동시 통화 수)는 따라요. `[확실]` 기존
  - 친구는 자기 것만 봐요. 다른 사람의 사용량·한도는 관리자 화면에만 있어요. `[확실]` D106 "자기가 자기꺼"
  - 계정 한도는 관리자만 바꾸고, 바꾸면 다음 요청부터 적용돼요. 진행 중인 통화는 끊지 않아요(기존 SPEC-390·394와 같음). `[추론]`
- Given–When–Then: Given 무제한 계정이고 `MARONG_DAILY_UNITS`가 10, When 오늘 단위가 50인 상태로 글을 보냄, Then 보내지고 티켓이 빠지지 않고 오늘 행만 늘어요.
- Given–When–Then: Given 기본 계정이고 `MARONG_DAILY_UNITS`가 비어 있음, When '내 마롱이'를 엶, Then 하루 한도가 '무제한'으로 보여요(유효 한도가 없으니까).
- Given–When–Then: Given 직접 계정(하루 200, 통화 월 비움)이고 `MARONG_CALL_PERSON_MONTHLY_USD`가 5, When 이번 달 그 사람 통화 비용이 5.1달러에서 통화를 시작함, Then 통화가 `budget_exhausted`로 거절돼요.
- External systems: 없음.
