## 요구사항

우선순위: Must(없으면 내보내지 않음), Should(첫 버전에 넣음, 늦어지면 뒤로), Could(되면 좋음). 상태: active(2026-11-23 체크포인트 통과, D135), deferred(미룸, D138).
'관리 페이지'는 `/chat/admin/` 아래의 화면 그룹이에요(TERM-176, D136 1-1로 바뀜). 관리자는 동희님 한 사람이에요.

## 흐름

REQ-570\~573은 [FL-200](../03-user-flow/FL-200-admin-overview.md)(개요에서 손볼 일 처리하기), REQ-577·578은 [FL-201](../03-user-flow/FL-201-admin-app-version.md)(새 버전을 올린 뒤 폰들이 받는지 보기)에 있어요. REQ-574\~576·582·583은 기존 흐름 FL-169·170·171·177·179·192의 관리자 쪽 첫 칸이 새 화면으로 바뀌는 것이라, 그 흐름의 바뀜 제안(아래 표 8·9·10)과 FL-200의 분기로 다뤄요. REQ-579는 FL-200의 비용 분기예요. REQ-580·581·585는 비기능이라 12 시험에서 봐요. REQ-585는 흐름의 칸을 바꾸지 않아요(넓은 폭의 SCR-201 왼쪽 회원 줄은 SCR-200의 '사람 줄 누름 → SCR-201'과 같은 동작이에요). REQ-584는 미룸 제안이라 흐름이 없어요.

- REQ-572와 REQ-579: 같은 숫자(통화 월 합, 그림 비용)를 개요는 요약으로, 비용 화면은 줄로 보여요. 개요는 API-280, 비용 화면은 API-280의 통화 칸과 API-266·236을 읽어요. 같은 때 읽으면 같은 값이에요.
- REQ-577과 REQ-575: 회원 한 사람 화면에서 '이 사람의 폰'을 보이려면 API-267의 폰을 회원에 맞춰야 해요. PR #101(커밋 `b54547d`)이 API-267에 `friendId`(회원 API와 같은 번호)를 더해서, 사람은 이 번호로만 맞춰요(SPEC-453, 기능 명세 3.5). 모순은 아니에요.
- REQ-577과 API-267의 상한: API-267은 폰을 친구마다 최근 20대, 모두 200대, 받아 감을 100명까지 줘요(PR #101 SPEC-438). REQ-577의 '폰마다'는 이 상한 안의 폰이고, 화면은 상한에 닿으면 알려요(SPEC-456).
- 기기 등록(API-105)의 새 폰 상한(409 `too_many_devices`)은 PR #101의 체크포인트에서 승인됐어요(D134, 2026-11-23, PR #101 기능 명세 8.9). 이 part의 요구사항은 그 동작에 기대지 않아요.
- REQ-581과 REQ-585: 360px 조건(REQ-581)은 그대로이고, REQ-585는 1024px 이상에서 같은 정보와 단추를 칸으로 나눠 보이라는 요구예요. 모순은 아니에요. 768\~1023px는 한 줄 기둥이라 REQ-581과 같은 배치예요.
- REQ-583(거두기)은 새 쓰기예요. 동희님이 질문 2에 '더함'으로 답하셔서(D137) Could로 넣고, SPEC-455·API-281도 active예요.
- 동희님 질문의 답(2026-11-23 체크포인트): 위 표 1\~12는 항목마다 '바꿈'(D136), 질문 2 초대 링크 거두기는 '더함'(D137), 질문 3 서버 셸 명령을 이번에 화면으로는 '미룸'(D138, 2026-12-23에 마롱이가 다시 봄). 질문과 근거는 [도메인 9절](../01-domain/admin.md#9-결정과-체크포인트2026-11-23)에 있어요.
