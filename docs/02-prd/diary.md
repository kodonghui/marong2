## 겹침·충돌·열린 질문

열린 질문(확인 질문, 추천안으로 이어 써요):

1. 일기 하루를 언제 끊을지: (가) 한국 시각 04:00(추천, 새벽 통화가 전날 일기에 들어가요) (나) 자정. REQ-139.
2. 일기 글을 어느 회사 모델로 쓸지: (가) Anthropic Claude(추천, 카톡 답과 뒤에서 하는 기억 정리가 쓰는 회사이고 처음 통화 설계에서도 자막 정리를 맡겼어요. DM 답은 2026-11-15부터 DeepSeek 중계가 먼저 받고 안 될 때 Claude가 대신 답해요) (나) 지금 통화 정리와 같은 구글 `gemini-3.8-flash`(통화 자막은 새 회사로 가지 않지만 카톡·DM 글이 구글로 가요). 2026-11-16 고침: 처음에 '카톡·DM 답과 같은 회사'라고 썼는데 DM 답은 DeepSeek 길이라 바로잡았어요. 요구사항에는 두지 않고 기능 명세의 AI 호출에 적어요.
3. 도장 받은 걸 마롱이가 어떻게 알지: (가) DM 답을 만들 때 도장 날짜만 읽기(추천, 지금 구조 그대로) (나) 도장을 찍으면 1:1 방 메모로 남기기(맥락끼리 서로 부르는 원이 없어지지만 메모가 쌓여요). REQ-155, 도메인 설계 6절 핫스팟.

그 밖에:

- 충돌 없음. 일기 말투는 D22로 정해졌어요(REQ-141).
- REQ-156·157(숨기기)은 지우기가 아니에요. 꼭 지워야 할 때는 지금처럼 동희님이 서버에서 직접 지워요(README '기록은 지워지지 않아요').
- REQ-163은 앱 글 대화의 로그인 규칙(Access JWT를 서버가 다시 확인하고 통화하는 친구를 찾음, `docs/app-chat.md`)을 그대로 따라요.
- REQ-165의 그림 월 예산은 통화의 월 예산(REQ-048\~052)과 따로예요. 통화 예산을 다 써도 일기는 쓰고, 그림 예산을 다 써도 통화는 돼요.
- 확인이 필요한 사실: 인공지능기본법의 생성물 표시 의무가 개인이 친구 몇 명에게 쓰는 앱에도 걸리는지(REQ-170은 걸리든 아니든 넣는 쪽이에요. 비용이 거의 없어요).
