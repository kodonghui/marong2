## 요구사항

우선순위: Must(없으면 내보내지 않음), Should(첫 버전에 넣음, 늦어지면 뒤로), Could(되면 좋음). 상태: active, proposed(질문의 답 대기), deferred(이번 버전에서 뺌). 이 문서의 행은 D104로 모두 active예요. 이 part가 기존 행을 바꾸면 그 행의 상태를 `changed(→ 대신하는 요구사항, 결정)`으로 적어요(아래 '기존 요구사항이 바뀌는 곳').
'친구'는 마롱이와 이야기하는 사람 한 명(TERM-162)이고, 가입한 지인도 친구예요. '관리자'는 동희님이에요. '시스템'은 앱 서버(TERM-194)와 통화 서버를 함께 가리켜요.

## 겹침·모순·열린 질문

- REQ-056과 PR #52: REQ-056과 D3은 글 답 본체에 LangGraph를 넣지 않는다고 했는데, PR #52가 글 답의 모델·도구 반복을 LangGraph로 옮겨 `main`에 합쳐졌어요. 이미 운영에서 돌고 있어서 요구사항을 지금 코드에 맞췄어요(위 표).
- REQ-018과 REQ-469: 뜻이 같아요. REQ-018은 남기고, REQ-469는 지금 코드(서버 전체에서 통화 하나)를 그 뜻에 맞추는 일과 설정값을 더해요.
- REQ-443과 D100: D100은 모든 계정에 지금 프롬프트를 그대로 쓰라는 말이고, D91은 반려동물 캐릭터일 때 19금 절을 끄라는 말이에요. 둘을 함께 읽어 '반려동물 캐릭터를 쓰는 계정만 뺌'으로 적었어요(Claude의 해석, 제안 2절에 적어 승인받음).
- REQ-462와 그림 화두: 반려동물 캐릭터를 쓰는 친구에게는 그림 화두를 보내지 않고 글 화두만 보내요(새 제안). 그림 화두 31장이 기본 마롱이 그림이기 때문이에요.
- 열린 질문: 없어요. 확인하지 못한 사실은 [도메인 설계 6절](../01-domain/unified.md#6-핫스팟)에 있어요.

## 범위 밖

이번 MVP에서 만들지 않는 것(제안 1절):

- 결제와 티켓 판매, 추억 모드(떠난 아이), 마롱이끼리 직접 대화, 웹 푸시, iOS 앱, 구글 로그인, 일반 웹페이지 읽기 도구, 공개 가입.
- 카카오톡과 디스코드 서비스(D92). 디스코드 봇과 디스코드 음성 중계는 끄고, 카카오 흔적은 문서에서 정리해요.
- 웹에서 안 되는 것: 푸시 알림, 전화 벨, 화면을 끄거나 다른 앱으로 간 동안의 통화 유지, 앱 스스로 업데이트.
- 도구 그룹 나누기, 일정 저장·취소 전 확인 버튼, 통화에서 도구 호출을 기다리지 않는 방식(2안), 끼어들기 감도 값 바꾸기.

서비스로 낼 때 다시 볼 것(지금은 안 함, 제안 18절, D103):

- 가입 고지·동의와 나이 확인, 지인 대화 기록의 열람 범위, 계정별 프롬프트(19금 절 포함), 글 답의 유료 공식 API, 티켓 판매와 결제, 탈퇴 때 자동 삭제, 가입 보호 강화(속도 제한, 봇 차단), 구글 로그인, 웹 푸시, 추억 모드, 마롱이끼리 대화, 도구 호출을 기다리지 않는 통화, 전체 합계 한도를 사람별로.
