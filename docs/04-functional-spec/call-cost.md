# 마롱이 통화 비용: 기능 명세

상태: 초안(2026-11-16, Claude). 명세 동결 전이에요. 지금 통화(Gemini 길: 웹 통화 서버와 디스코드 음성 중계)에 사용량 기록과 월 예산을 다시 걸고, 설정 실험·시험 도구를 더해요. 엔진과 목소리는 바꾸지 않아요.
입력: [통화 비용 요구사항](../02-prd/call-cost.md) REQ-179\~201과 [통화 요구사항](../02-prd/requirements.md)의 예산 규칙 REQ-048\~052, [사용자 흐름](../03-user-flow/) FL-120\~123, [도메인](../01-domain/domain.md)의 CTX-002·CTX-006(2026-11-16 Gemini 길)과 TERM-034\~039, 처음 통화 명세 [spec.md](spec.md)의 SPEC-023(예산 세기와 막기)·SPEC-025(관리 명령)·SPEC-026(시트), Notion 연구 행(2026-11-16) 2·3·7·11절.
뒤 단계: 05 ERD는 `marong/call/migrations/007_call_cost.sql`, 06 API는 통화 서버 `GET /api/me`의 바뀐 칸과 듣기 시험 API, 07 사이트맵은 통화 홈의 예산 상태와 듣기 시험 화면이 이 SPEC 번호를 따라가요. 함께 설계한 일기는 [diary.md](diary.md)예요.

## 1. 모든 행에 공통인 규칙

- 어디서 도나: 웹 통화 서버(`tools/vertex_live/server.py`)와 디스코드 음성 중계(`tools/vertex_live/discord_relay.py`)는 따로 도는 프로세스이고, 둘 다 `LiveSession`(`live_session.py`)으로 구글에 붙어요. 사용량 기록·예산 확인·설정 실험은 `LiveSession`과 `MemoryStore`(`call_memory.py`)에 넣어서 두 입구가 같은 코드를 써요. DB 역할은 지금처럼 `marong_call`이에요. 디스코드 음성 봇(`tools/discord_voice/index.mjs`)은 중계에 묻고 들어가요.
- 받는 고리: 구글에서 온 메시지를 읽는 고리(`receiver`) 안에서는 기다리거나 DB를 부르지 않아요(`live_session.py` 머리말 규칙). 사용량은 숫자만 꺼내 메모리 대기열에 넣고, 저장은 뒤의 일꾼이 해요(REQ-197).
- 시각과 달: 저장은 UTC, 이번 달은 UTC 달이에요(처음 예산 설계 SPEC-023과 같음, 한국 시각으로 매달 1일 오전 9시에 바뀜).
- 돈: 달러, 저장은 소수 여섯째 자리까지, 보기는 둘째 자리까지예요.
- 내용 없음: 통화 사용량·관리 명령·시트·로그에는 숫자와 이름표(통화 id, 구간 id, 입구, 설정 실험 이름, 모델 이름)만 있어요. 자막·지시문·기억 묶음·검색어는 없어요(REQ-195).
- 친구 화면: 현경님 화면에는 금액·퍼센트·남은 시간을 보이지 않아요. 막힐 때만 마롱이 말투로 알려요(처음 설계 REQ-048·050, 친구 먼저).
- 확실도 표시: [사실] 문서나 코드에서 확인, [추정] 근거 있는 짐작, [확인 필요] 실기기나 실제 계정에서 봐야 함.

### 3.4 조용할 때 문(SPEC-178)

1. 친구 소리 20ms 조각마다 RMS(−1\~1로 맞춘 값)를 재요.
2. 닫힌 문: `quiet_rms` 이상인 조각이 2개 이어지면 열어요. 열 때 앞 300ms(15조각)를 먼저 보내요. 닫힌 동안은 앞 300ms만 메모리에 들고 있어요.
3. 열린 문: 마지막으로 `quiet_rms` 이상이었던 조각 뒤 1초까지 보내고 닫아요. 닫을 때 `audioStreamEnd`를 한 번 보내요.
4. 글로 갈아타기·다시 잇기 때는 문 상태를 그대로 이어 가요.
5. 구간마다 '보낸 초'와 '안 보낸 초'를 숫자로 남겨 실험끼리 비교해요.

### 3.5 글로 갈아타기 순서(SPEC-179)

1. 갈아탈 차례가 되면(마지막 턴 입력 토큰 > `handoff_tokens`) 조용한 틈을 기다려요.
2. 틈이 오면 새 연결을 열어 설정을 보내요. 이전 연결은 계속 마이크 소리를 받아요.
3. 10초 안에 `setupComplete`를 받고, 그때까지 아무도 말하지 않았으면 바꿔요. 아니면 새 연결을 닫고 30초 뒤 다음 틈에 다시 해요.
4. 바꿀 때 한 트랜잭션으로 이전 구간을 닫고(`handoff`) 새 구간(`handoff`, 설정 실험 이름 포함)을 열어요.
5. 마이크 소리를 새 연결로 돌리고, 바꾸기 직전 1초 소리를 먼저 보내요. 이전 연결은 닫아요(그 연결의 남은 사용량은 이전 구간으로 저장).
6. 새 연결의 이어 받기 핸들을 그 뒤 다시 잇기에 써요.

## 7. 실기기·실계정에서 확인할 것

### 7.1 구현 전(개발 서버, `probe_live.py`)

- Vertex 연결의 `usageMetadata`: 칸 이름, 오는 때(턴 끝·`turnComplete`와 같은 메시지인지), 턴마다인지 누적인지(→ `usage_mode`), 모달리티 상세가 오는지, 생각·자막 토큰이 어디에 들어가는지, 캐시 토큰이 오는지.
- `audioStreamEnd`가 지금 말 끝 감지(`explicitVadSignal`)와 같이 될 때 말이 잘리거나 대답이 늦어지지 않는지.
- 핸들 없는 새 연결을 이전 연결과 겹쳐 열 때 `setupComplete`까지 걸리는 시간(목표 2초).

### 7.2 운영(첫 2주)

- 구글 청구서(Cloud Billing 보고서)와 `call-cost` 합계 비교(10% 안이면 맞음으로 봄).
- 지출 상한 예산이 걸렸을 때 Live 연결이 돌려주는 오류 모양(일부러 걸 수 없어서 처음 걸릴 때 로그로 봄).
- 동희님 준비물: 구글 지출 상한 예산(서버 120%인 180달러보다 높게, 예: 200달러), 크레딧 잔액 확인.
- 웹 조용할 때 문을 켠 실험에서 현경님이 말이 잘렸다고 느끼는지(첫 낱말).
