## 05 저장 방식

TBL-102의 `answered_at`은 최초 수락 시각입니다. TBL-003의 `status`에는 예약·연결 준비·정상 연결이 모두 `live`로 표시될 수 있습니다. `last_beat_at`은 다른 동작에서도 갱신됩니다. TBL-004의 구간 시각은 모델이나 연결 구간의 준비·교체·닫힘을 나타냅니다. 최초 연결과 복구 대기 전환을 재시작 뒤 구분하려면 알림 통화의 시각 두 개를 TBL-003에 저장하는 안을 추천합니다. [기존 통화 스키마](https://github.com/kodonghui/marong2/blob/9811ad9305ec1c47b41ec85f81d8e111f96628f7/marong/call/schema.sql#L49-L80) · [현재 예약과 연결](https://github.com/kodonghui/marong2/blob/823e5d420f5ed4edd22dcff1df0d73c311a3e4b4/tools/vertex_live/call_memory.py)

| TBL-003 추가 필드 | 형식 | 의미 |
| --- | --- | --- |
| `notice_first_connected_at` | `timestamptz`, NULL 허용 | 기존 소유자와 통화 ID에 대해 서버가 첫 연결 준비를 확인한 시각. 한 번만 기록하며, 이후 복구·종료에서도 최초 값으로 남깁니다. |
| `notice_connection_deadline_at` | `timestamptz`, NULL 허용 | 현재 기다리는 첫 연결 또는 복구의 종료 기한. 첫 수락 시각 또는 서버가 전환을 확정한 단절 시각에 120초를 더해 정해진 기한을 직접 저장합니다. 연결이 유효해지거나 끝났을 때 비웁니다. |

첫 연결을 아직 확인하지 않은 새 예약은 첫 시각이 NULL이고 기한이 있습니다. 연결 중에는 첫 시각이 있고 기한이 NULL입니다. 단절 확정으로 복구 대기에 들어가면 첫 시각과 새 기한이 모두 있습니다. 재연결이 확인되면 그 기한만 비웁니다. 알림으로 수락한 약속 전화에 이 필드를 사용합니다. 기존 일반 통화, Android 수락, 만료 뒤 별도 일반 발신은 원래 계약을 따릅니다.

기존 행은 두 필드가 모두 NULL인 상태로 둡니다. 과거 첫 연결·단절 시각은 추정하거나 채우지 않습니다. 아직 끝나지 않은 이전 초안 예약이 시험 환경이나 출시 준비에서 발견되면 자동 종료로 넘기기 전에 해당 환경의 상태를 확인합니다. 데이터 삭제나 운영 변경 권한은 기존 승인 절차를 따릅니다.

통화 스키마의 011 다음에 012 마이그레이션을 추가하는 안입니다. 마이그레이션은 시각 필드 두 개와 그 설명을 추가하며 기본값과 기존 행의 갱신은 없습니다. 통화 서버의 기존 쓰기 권한을 사용하며 앱·카카오에 새 쓰기 권한을 주지 않습니다. 기존 호출자·통화 잠금과 열린 통화의 유일 조건을 사용합니다. [기존 011 통화 마이그레이션](https://github.com/kodonghui/marong2/blob/9811ad9305ec1c47b41ec85f81d8e111f96628f7/marong/call/migrations/011_admin_month.sql)

## 06 상태 확정과 08 화면 연결

1. 최초 수락 트랜잭션에서 TBL-102에 기록한 `answered_at`을 같은 예약의 첫 연결 기한에 사용합니다. API-315의 결과 확인, 새 연결 토큰 발급, API-314와 자동 조회는 기한을 수정하지 않습니다.
2. 같은 소유자의 API-317 연결은 호출자·약속 전화·통화의 기존 잠금 순서에서 서버 시각과 기한을 검사합니다. 통화 준비가 확정되면 첫 시각과 기한을 한 번 갱신합니다. 첫 준비가 실패하거나 철회되면 처음 기한을 유지합니다. 해당 통화를 사용하는 정상 연결 또는 기한 안에 서버가 받은 유효 복구는 현재 소유권과 준비 상태를 대조해 보호합니다.
3. 서버가 해당 연결의 단절과 복구 대기 전환을 처음 확인하면 그 시각부터 120초를 기록합니다. 같은 전환의 반복, 실패한 복구, 오래된 연결의 종료 메시지는 기한을 연장하지 않습니다. 서버 재시작이 정상 연결을 복구 대기로 처음 전환하는 경우와 이미 기한이 있는 재시작을 구분합니다.
4. 서버 시각이 기한에 도달했으면 잠금 아래 최신 소유와 연결을 확인합니다. 보호해야 할 연결이 없을 때 기존 종료 처리로 해당 통화를 끝냅니다. 수락 결과의 원래 통화 ID와 약속 전화의 수락 이력을 보존합니다. 같은 행의 반복 종료는 결과가 같습니다. 종료 이후 늦은 연결은 해당 통화를 열지 못합니다.
5. SCR-002에서 기존 통화가 종료된 것이 확인되면 종료 안내를 보이고 `다시 걸기`를 별도 선택으로 제공합니다. 결과를 확인 중인 상태는 기존 화면을 사용합니다. 이미 처리된 약속 전화에 대한 수락은 다시 만들지 않습니다. [기존 SCR-002 화면 규칙](https://github.com/kodonghui/marong2/blob/9811ad9305ec1c47b41ec85f81d8e111f96628f7/docs/08-screens/iphone-home-webapp-notifications/SCR-002.md#화면-규칙)
