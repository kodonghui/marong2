# SCR-114 말로 고치기

Purpose: 친구가 일기에서 틀린 것을 말로 알려 주면 마롱이가 그 말대로 새 판을 쓰는 칸이에요. 지난 판은 남아요. (FL-116)

주소: `/chat/diary/:date#fix`. 한 날(SCR-113) 위에 아래에서 올라오는 칸이에요. 바로 이 주소로 열면 한 날을 먼저 불러온 뒤 열어요.

| Data | Source |
| --- | --- |
| 지금 판 번호, 남은 고치기 수, 막힌 이유 | API-110 (한 날이 불러 둔 값) |

| Action | Result | Failure |
| --- | --- | --- |
| 고칠 말 쓰기 | 1\~200자, 남은 글자 수 "12/200". 띄어쓰기만 있으면 '고쳐 줘'가 꺼짐 | 200자를 넘게 붙여 넣으면 200자에서 자르고 "200자까지 쓸 수 있어" |
| '고쳐 줘' | API-111(`revision`, `text`, 새 `Idempotency-Key`) → 200 → 칸이 닫히고 한 날이 새 판, 고친 횟수 하나 늚(SPEC-160). `sceneChanged=true`면 SCR-113#scene-changed | 아래 상태들. 실패한 고치기는 횟수에 세지 않아요 |
| 닫기(×, 칸 밖 누르기, 브라우저 뒤로) | 칸이 닫힘. 쓴 말은 이 날을 다시 열 때까지 남음(`sessionStorage`) | 보내는 중에 닫아도 답은 한 날에 보임 |

| State | What the user sees and can do | From responses |
| --- | --- | --- |
| SCR-114#normal | 제목 "어디가 달랐어?", 안내 "고쳐 줄 말을 적어 줘. 예: 떡볶이가 아니라 라면이었어", 글 칸, "12/200", "4번 더 고칠 수 있어", '고쳐 줘'(52px) | |
| SCR-114#sending | 글 칸과 버튼이 꺼지고 "마롱이가 고치는 중이야…"(보통 수십 초, 90초까지). 닫을 수는 있음. 답이 200이면 칸이 닫히고 한 날이 SCR-113#normal(새 판)이나 SCR-113#scene-changed | API-111#200 |
| SCR-114#input-error | 글 칸 아래 빨간 글 "뭔가 잘못 보냈나 봐. 다시 해 볼게"(`reason`이 `required`면 "고칠 말을 적어 줘", `too_long`이면 "200자까지 쓸 수 있어"), 쓴 말은 그대로 | API-111#400 |
| SCR-114#failed | 쓴 말 그대로, "지금은 못 고쳤어. 조금 있다가 다시 해 볼래?", '다시 보내기'(새 키). 남은 횟수 그대로 | API-111#503(`fix_failed`) |
| SCR-114#rate-limited | 쓴 말 그대로, "너무 빨라! 조금 있다가 해 줘"와 남은 초(`Retry-After`), 그동안 버튼 꺼짐 | API-111#429(`too_many_requests`) |
| SCR-114#stale | `stale_revision` → 한 날을 다시 불러오고 칸은 열어 둔 채 "그 사이 일기가 바뀌었어. 새로 보여 줄게", 쓴 말 그대로 다시 보낼 수 있음. `busy` → 칸을 닫고 SCR-113#fixing. `not_ready` → 칸을 닫고 한 날이 그 상태. `fix_limit` → 칸을 닫고 SCR-113#limits | API-111#409 |
| SCR-114#permission | 401 → 쓴 말을 남기고 페이지를 새로 불러 Access 로그인, 돌아오면 칸을 다시 열고 쓴 말을 넣어 둠. 403 `not_allowed`·`no_dm` → 칸을 닫고 SCR-113#permission. 403 `cross_site` → "이 화면에서 다시 해 줘"(자동으로 다시 보내지 않음) | API-111#401, API-111#403 |
| SCR-114#error | 쓴 말 그대로, `db_unavailable`이면 "잠깐 문제가 생겼어. 조금 있다가 다시 해 줘", 그 밖은 "잠깐 문제가 생겼어. 다시 해 볼래?"와 추적 id, '다시 보내기' | API-111#503(`db_unavailable`), API-111#default, 네트워크 없음·시간 넘김 |

- 멱등 키: '고쳐 줘'를 누를 때마다 새 키를 만들어요. 답을 못 받고 끊겼을 때(네트워크 없음·시간 넘김)만 같은 키로 다시 보내요. 같은 키는 처음 답을 그대로 돌려주니까(06 결정 6), 실패 답을 받은 뒤 '다시 보내기'는 새 키예요.
- loading·empty: 한 날이 불러 둔 값을 써서 따로 불러오지 않아요. 빈 칸으로 열리는 것이 처음 모습이에요(#normal).
- 고칠 말은 `textContent`로만 보이고, 한 날 응답과 로그에 남지 않아요(REQ-177).
- 경우의 종류: 접근(#permission), 입력(#input-error, 200자), 상태 변화(#stale의 `not_ready`), 반복(보내는 동안 버튼 꺼짐, 멱등 키), 동시(#stale), 한도(남은 수, `fix_limit`, #rate-limited), 바깥 서비스(#failed: 모델 실패는 모두 `fix_failed`, 06 결정 7), 데이터 노출(새 판의 글만 돌아오고 장면·하루 모음은 없음), 끊긴 흐름(보내는 중 닫기, 끊기면 같은 키로 다시), AI 답(새 판은 한 날 화면에 그대로, 못 고치면 지금 판 그대로).
