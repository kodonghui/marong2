# SCR-123 글 대화 안 고르기 카드

Purpose: 마롱이 말 아래에 붙은 고르기 칸으로 첫 질문, 약속 초안 확인, 약속 바꾸기 제안, 지지 방식 묻기, 민감 기억 허락, 전하기 확인, 밤 전화 확인에 한 번 눌러 답하는 부품이에요. (FL-124, FL-125, FL-127, FL-129, FL-130, FL-134, FL-138)

자리: 글 대화(SCR-107)와 글 대화 창(SCR-112)의 마롱이 말 가운데 `card`가 있는 말. 화면 주소가 따로 없어요. 디스코드는 같은 카드를 단추로, 카톡은 번호로 보여요(봇 안의 처리, 이 정의 밖).

목업(09단계): 후보 A·B는 [`design/persona-candidates.md`](../../design/persona-candidates.md). 방향을 정하면 이 줄에 대지 이름을 적어요. 다르면 이 정의가 맞아요.

| Data | Source |
| --- | --- |
| 묻는 글(그 말의 `text`), 카드 id, 종류, 첫 질문 차례, 칸(값과 글), 상태, 고른 값, 닫히는 때 | API-102·104의 `Message.card`(app-chat 0.4.0) |
| 고른 뒤 결과(카드의 새 상태, `effect`, 새 약속 문장) | API-136 |

모양: 말풍선 바로 아래, 말풍선과 같은 왼쪽 줄에 칩 그룹(`role="radiogroup"`, 이름은 묻는 글). 칩 높이 48px, 칸 글은 서버 상수라 20자까지, 좁으면 칩이 다음 줄로 감기고, 칸 글이 말풍선 폭보다 길면 칩 안에서 두 줄로 감겨 칩이 높아져요. 첫 질문은 그룹 위에 작은 글 "1/3"(`step`). 카드 아래 작은 글로 닫히는 때를 보이지 않아요(닫히면 상태로 알려요).

종류별 칸(서버 상수). 첫 질문·초안·제안·민감 기억은 명세 3.9·SPEC-193·196·231의 칸이고, [새 제안]은 이 정의에서 처음 정한 글이에요(2차 논의에서 봐 주세요):

| 종류 | 칸 |
| --- | --- |
| `card_question` | 1: 그냥 들어주기·내 편·같이 방법 찾기·기분 전환·그냥 수다·그때그때 물어봐, 2: 물어볼 때만·괜찮아 보이면 가끔·언제든, 3: 부드럽게·솔직하게·그냥 넘어가 줘 |
| `card_draft` | 맞아·고칠래 |
| `card_proposal` | 응·아니 |

| `relay_confirm` | 맞아·취소(SPEC-238의 "맞지?"와 취소) |

| --- | --- | --- |
| 칸 누르기 | API-136(그 값) → 카드가 #answered로 바뀜. `effect`마다: `next_question`이면 다음 질문 카드가 새 마롱이 말로 붙어 기다리기(API-104)로 와요. `card_set`·`proposal_accepted`면 알림 조각 "약속 정했어"와 '보기'(SCR-120). `open_card_screen`이면 `/chat/persona/?from=draft`로 감. `memory_forgotten`이면 "잊었어". 나머지는 카드 상태만 | 409 `card_closed` → 칸을 막고 "이 카드는 이제 못 골라", 대화를 다시 불러 지금 상태를 보임. 404 → 카드를 접고 대화를 다시 불러옴. 400 → 짧은 말 "뭔가 잘못 보냈나 봐. 다시 해 볼게", 칸 다시 켬. 503·`default`·네트워크 → 카드 아래 짧은 말과 '다시 해 볼게'(같은 값으로 다시, 같은 값은 처음 결과라 두 번 세지 않음) |
| '보기'(알림 조각) | SCR-120 | 없음 |

- 카드가 붙은 말의 글은 늘 그대로 보여요. 카드를 못 그리는 경우(열어 둔 옛 페이지, 스크립트 실패)에도 친구는 칸 글을 글로 써서 답할 수 있어요(명세 3.9의 카톡과 같은 처리, SPEC-197 '말로 답함'). 글 대화는 봇이 내보내는 페이지라 앱 버전과 상관없이 새 chat.js가 카드를 그려요(API 계약 app-chat 8의 Open을 이렇게 닫음).
- 지난 카드: 대화를 위로 올려 보이는 옛 카드도 지금 상태로 보여요. 첫 질문·초안·제안·지지 방식 묻기·밤 전화 확인은 친구마다 종류별로 하나만 열려 있어서(TBL-119 유니크) 새 카드가 오면 옛 것은 `replaced`예요. 민감 기억 허락과 전하기 확인은 대상마다 하나라 여러 개가 같이 열려 있을 수 있어요.
- `relay_confirm`의 전할 말과 받는 친구 이름은 묻는 글(`text`) 안에 있어요. 카드에는 칸만 있어요.
- 경우의 종류: 반복(누른 뒤 막음, 같은 값은 처음 결과), 상태 바뀜(다른 채널에서 답함 → 다시 불러 #answered), 대상(없는 카드 404), 데이터 노출(카드에 친구 글 없음, 칸 글은 서버 상수), 화면 상태(360px에서 첫 질문 1의 6칸이 세 줄, 430px에서 두 줄).
