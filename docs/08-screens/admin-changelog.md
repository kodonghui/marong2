## 1. SCR-220 업데이트 내역

Purpose: 관리자가 마롱이에 언제 무엇이 더해지고 나아지고 고쳐졌는지를 반영 단위마다 '변경 전·변경 후'로 읽어요. (FL-215, REQ-620\~622, TERM-270·271)

| Data | Source |
| --- | --- |
| 반영 단위 목록(새것부터): 이름, 반영일 또는 차례 날짜, 서버·앱, 앱 버전 이름·코드, 지난 기록에서 채움, 근거 | API-300 `units[]` |
| 항목: 구분, 영역, 항목 이름, 변경 전, 변경 후, 근거 | API-300 `units[].items[]` |
| 읽지 못한 파일 수 | API-300 `skipped` |
| 고른 영역 | 화면 안(서버에 보내지 않고 주소에도 남기지 않음. 새로 고치면 '전체') |

| State | What the user sees and can do | From responses |
| --- | --- | --- |
| SCR-220#loading | 제목·설명·칩 줄은 바로 그리고, 그 아래 회색 자리: 그룹 머리 둘과 그 아래 카드 셋(넓은 폭은 표 줄 셋). 받은 뒤 자리가 움직이지 않아요 | (API-300 기다림) |
| SCR-220#normal | 칩 '전체'가 골라짐. 세는 줄 '반영 {m}번 · 항목 {n}개'. 반영 단위마다 그룹: 머리 '{날짜} · {이름}', 그 아래 작은 줄 '서버 반영 · PR #…' 또는 '앱 {버전 이름}({코드}) · PR #…'. 그룹 아래 항목 표(폭마다 2절). 근거는 새 창 링크 | API-300#200(`units` 1개 이상) |
| SCR-220#filtered | 칩 하나(예: '통화')가 골라짐(`aria-pressed="true"`). 그 영역의 항목만 보이고, 남은 항목이 없는 그룹은 통째로 숨겨요. 세는 줄이 거른 뒤의 수로 바뀜. 서버를 다시 부르지 않아요 | 칩 누름(같은 응답) |
| SCR-220#filter-empty | 고른 영역의 항목이 하나도 없음: 칩 줄 아래 '이 영역의 내역이 없어요'와 '전체 보기' 단추(누르면 #normal). 세는 줄은 숨기고, #skipped 줄은 그대로 둬요 | 칩 누름(같은 응답) |
| SCR-220#empty | '아직 적은 업데이트 내역이 없어요' 한 줄. 칩 줄은 꺼짐(누를 수 없음) | API-300#200(`units: []`, `skipped` 0) |
| SCR-220#unreadable | '내역 파일 {k}개를 읽지 못했어요' 한 줄. 칩 줄은 꺼짐. 파일은 있는데 모두 검사에 걸린 때라 #empty로 보이면 고장이 숨어요 | API-300#200(`units: []`, `skipped` 1 이상) |
| SCR-220#skipped | 세는 줄 아래 회색 작은 글 '읽지 못한 내역 파일 {k}개는 빼고 보여요'. 나머지는 #normal 그대로 | API-300#200(`skipped` 1 이상) |
| SCR-220#no-date | 반영 기록이 없는 지난 단위: 머리의 날짜는 `sortOn`(PR을 합친 날)이고, 작은 줄 앞에 '반영일 기록 없음 · 날짜는 PR을 합친 날 ·'이 붙어요 | API-300#200(`deployedOn: null`) |
| SCR-220#backfilled | 지난 기록에서 채운 단위: 머리 오른쪽(폰은 머리 아래)에 작은 테두리 표 '지난 기록에서 채움'. '없음'과 그 단위 항목의 '기록 없음'은 회색 기울임(명세 3.4) | API-300#200(`backfilled: true`) |
| SCR-220#long | 이름 40자, 항목 40자, 변경 전·후 100자: 칸 안에서 줄바꿈하고 칸 밖으로 나가지 않아요. 영문·숫자가 길게 이어져도 끊어 줄바꿈해요 | API-300#200(긴 글) |
| 공통#error | 그룹 자리에 '잠깐 문제가 생겼어요. 다시 해 볼까요?'와 '다시 해 볼게요'(API-300 다시). 칩 줄은 꺼짐 | API-300#500, 네트워크 실패 |
| 공통#forbidden | admin.md 1절 그대로 | 화면 경로 403, API-300#403 |
| 공통#stale | admin.md 1절 그대로(60초 넘게 숨겼다 보이면 API-300을 한 번 다시 읽음). 고른 칩은 그대로 둬요 | (다시 읽기) |

| Action | Result | Next state |
| --- | --- | --- |
| 탭 '업데이트 내역' | 이 화면을 새로 받아요(관리 페이지 3.1과 같음) | #loading |
| 영역 칩 | 같은 응답을 화면에서 거름 | #filtered 또는 #filter-empty |
| 칩 '전체', '전체 보기' | 거르기를 풂 | #normal |
| 근거 링크 | 공개 저장소의 PR·커밋을 새 창으로 엶. 관리 페이지는 그대로 | (그대로) |
| 다시 해 볼게요 | API-300 다시 | #loading |

- 이 화면에는 쓰기 단추가 없어요. 내역은 반영 절차가 저장소에서 써요(FL-216).
- 모든 글은 `textContent`로 넣어요. 글에 `<img …>` 같은 것이 있어도 글자로 보여요(SPEC-502).
- 칩은 `<button aria-pressed>`이고 높이 44px 이상이에요. 칩 줄은 폭이 좁으면 두 줄로 접혀요(옆으로 밀리지 않음).

## 2. 폭과 배치

| 폭(CSS px) | 배치 | 항목 한 줄의 모양 |
| --- | --- | --- |
| 1023px까지(폰 360·430px, 태블릿 세로) | admin.md 1절의 한 줄 기둥(본문 최대 720px, 좌우 16px) | 카드 하나: 첫 줄 구분 표·영역·항목 이름(굵게). 둘째 줄 두 칸(왼쪽 '변경 전', 오른쪽 '변경 후', 칸 사이 8px). 셋째 줄 작은 이름 '근거'와 링크(작은 글, '·'로 이음) |
| 1024px부터(노트북 1280·1440px) | admin.md 1.1절의 넓은 배치에서 '한 칸'(본문 최대 1200px) | 표 한 줄: 구분 72px · 영역 104px · 항목 22% · 변경 전 · 변경 후(남은 폭을 반씩) · 근거 112px. 칸 머리 줄은 그룹마다 맨 위에 |

- 같은 HTML(`<table>`, 칸마다 `role`을 적음)이고 CSS 미디어 질의 `min-width: 1024px` 하나로만 바뀌어요(명세 3.4). 폭을 바꿔도 다시 읽지 않고 고른 칩이 그대로예요.
- 360px 카드의 두 칸은 한 칸 약 147px(본문 328px − 카드 안 여백과 테두리 26px − 칸 사이 8px의 반)이에요. 목업에서 측정한 값은 140px인데, 목업 칸의 세로 스크롤 막대 15px만큼 좁아서예요. 100자 글이 여덟 줄이었어요(#long). 1280px 표의 변경 전·후 칸은 324px, 1024px는 224px였어요.
- 탭 줄: 360px에서 탭 일곱(폭 합 505px)이 탭 줄(328px)에 들어가지 않아 탭 줄 안에서만 옆으로 밀리고 오른쪽 끝을 흐리게 해요(admin.md 1절 규칙 그대로). 처음 그릴 때 지금 탭이 탭 줄 밖이면 탭 줄만 밀어 지금 탭이 보이게 해요(새 제안, 4-7). 그러지 않으면 이 화면에서 '업데이트 내역' 탭이 통째로 가려져요. 1024px부터는 탭 일곱이 한 줄에 다 들어가요(본문 960px, 4-8, TC-709가 측정).
- 그룹 머리는 넓은 폭에서도 표 위 한 줄이에요(머리를 표 안의 칸으로 넣지 않음). 그룹 사이 24px(`space.lg`)예요.
- 읽는 차례: 제목 → 설명 → 칩 줄 → 세는 줄(#skipped 줄) → 그룹(머리 → 작은 줄 → 표의 줄들). Tab 키는 칩 일곱 → 그룹마다 근거 링크 차례예요. 폰과 넓은 폭의 차례가 같아요.
