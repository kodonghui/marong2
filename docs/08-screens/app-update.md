# 앱 자동 업데이트가 바꾸는 화면 상태(CTX-021)

08단계 정의예요(2026-11-17, Claude 제안, 검토 대상). 새 화면은 안드로이드 알림 하나(SCR-130)이고, 있는 화면에는 글 대화 메뉴(SCR-109)에 줄 하나가 늘어요([07 사이트맵](../07-sitemap/sitemap.md)). 바탕 정의는 [app-chat.md](../app-chat.md)(SCR-109)예요. 입력: 기능 명세 [app-update.md](../04-functional-spec/app-update.md)(SPEC-284\~302), 계약 [app-update.openapi.yaml](../../api/app-update.openapi.yaml)(API-141, API-142).

2026-11-22 기능 변경(Claude 마롱이 봇, 체크포인트 전): 통화 홈 SCR-001과 글 대화 SCR-107에 같은 업데이트 배너(TERM-224)가 늘어요(D129·D130·D131, [통화 홈 절](#scr-001-통화-홈의-업데이트-배너2026-11-22), [글 대화 절](#scr-107-글-대화의-업데이트-배너2026-11-22)). '지금 설치'를 누르면 앱 창이 떠 있어도 설치해요(D128). 바뀐 곳은 아래 공통 규칙 두 줄과 '바뀌지 않는 화면'의 통화 홈 줄·글 대화 줄이고, 승인된 글은 두 절 끝에 옮겨 두었어요. 입력은 기능 명세 8절 SPEC-439\~441·443이에요. SCR-109·SCR-130의 상태는 그대로예요.

공통 규칙:

- 자동 업데이트는 조용히 일어나요. 받기와 설치에는 화면이 없고, 설치가 끝났다는 알림도 없어요(REQ-324, 확인 질문 3의 추천안). 사람이 보는 것은 안드로이드가 확인을 요구할 때의 알림(SCR-130)과 처음 한 번 허용하는 메뉴 줄(SCR-109)뿐이에요. 2026-11-22부터는 받아 둔 새 버전이 설치를 기다리거나 자동 업데이트가 꺼져 있으면 통화 홈과 글 대화의 업데이트 배너(SCR-001#update-ready·#update-off, SCR-107#update-ready·#update-off)도 보여요(D129·D130·D131).
- 업데이트가 깔리면 안드로이드가 앱을 끝내요. 앱 창이 화면에 떠 있으면 설치를 미루니(REQ-319) 쓰는 도중에 창이 닫히지 않아요. 다음에 열면 새 버전이에요. 2026-11-22부터 친구가 배너의 '지금 설치'를 누른 때만 쓰는 도중에 창이 닫혀요. 배너가 먼저 '앱이 잠깐 닫혀'라고 알려요(D128, SCR-001#update-installing).
- 안드로이드가 그리는 화면(설치 확인 창, '출처를 알 수 없는 앱 설치' 설정)은 우리가 바꾸지 않아요. 문서에는 들어가고 나오는 경로만 적어요.
- 색·글꼴·간격은 지금 글 대화 메뉴의 토큰을 그대로 써요. 새 토큰은 없어요. 화면 공통 기준(토큰, 부품, SCR 번호표, 목업 한 벌)은 '마롱이의 일기 설계하기' 작업이 맡아요(동희님 2026-11-17 12:36 "걔들이랑 합쳐서 작업해야할거같아"). 이 문서의 상태는 그쪽 목업 한 벌에 들어갔어요: [공통 목업 캔버스](https://claude.ai/artifact/CC154gunovJS3tqa8XkpZ9)(2026-11-17 버전 13)의 `C021-109-*` 대지 넷과 `C021-130-notification`. #update-none은 줄이 없는 상태라 그리지 않았어요.
- 폭은 세로 휴대폰 360\~430px, 테마는 낮(군밤 크림)·밤(밤하늘) 둘 다예요([README](README.md) 공통 규칙).

## SCR-001 통화 홈의 업데이트 배너(2026-11-22)

Purpose: 받아 둔 새 버전을 친구가 바로 깔게 하고, 자동 업데이트가 꺼져 있으면 첫 화면에서 켜게 해요. (FL-148, REQ-560, REQ-561, REQ-321, REQ-325, D128\~D130)

바탕 정의는 [SCR-001.md](SCR-001.md)예요. 배너는 그 화면의 다른 상태(#normal, #budget, #error 등) 위에 겹쳐 붙는 띠라서, 아래 상태는 SCR-001의 다른 상태와 함께 있어요.

| Data | Source |
| --- | --- |
| 받아 둔 새 버전이 있는지와 그 버전 이름(`updateState()`: `none`·`ready`·`installing`) | 앱 연결 `window.__marongApp.updateState()`(SPEC-440). 서버 API 없음 |
| 자동 업데이트를 할 수 있는지(`installUpdates`) | 앱 연결 `deviceState()`(SPEC-301, SCR-109와 같음) |
| 앱 연결의 버전(`window.__marongApp.version`) | 앱이 넣는 연결. 3 이상일 때만 배너를 그려요(REQ-561) |

| Action | Result | Failure |
| --- | --- | --- |
| '지금 설치' 누르기 | `installUpdate()`(SPEC-441). 단추가 바로 막히고 #update-installing. 안드로이드가 앱을 닫고 새 버전을 깔아요. 다시 열면 새 버전이고 배너는 없어요. 안드로이드가 사람의 확인을 요구하면 확인 창이 바로 떠요(SCR-130의 알림 대신) | `busy`(통화·벨 중) → #update-busy. `failed` → #update-failed. `none`(받아 둔 파일이 사라짐) → 배너를 다시 읽어 #update-none |
| '켜기' 누르기(#update-off) | `openInstallSettings()`. 안드로이드의 '출처를 알 수 없는 앱 설치'에서 마롱이 화면이 열려요. 켜고 돌아오면(`visibilitychange`) 다시 읽어 배너가 사라져요 | 그 설정 화면이 없는 폰 → 앱 정보 화면(SPEC-301). 켜지 않고 돌아오면 #update-off 그대로 |

| State | What the user sees and can do | From responses |
| --- | --- | --- |
| SCR-001#update-ready | 인사 줄 위, 화면 위쪽에 띠 하나: 왼쪽 '새 버전 준비됨 (0.3.3)', 오른쪽(좁으면 아래) '지금 설치' 단추. 단추는 SCR-109의 '켜기'와 같은 모양(누르는 높이 44px 이상). 닫기 단추는 없어요(받아 둔 파일이 있는 동안 늘 보임, REQ-321) | `updateState()` = `ready` |
| SCR-001#update-installing | 같은 띠에 '설치하는 중… 앱이 잠깐 닫혀'. 단추 대신 진행 표시(돌아가는 점). 통화 단추는 그대로 쓸 수 있지만 곧 앱이 닫혀요 | `installUpdate()` = `installing`, 또는 `updateState()` = `installing` |
| SCR-001#update-busy | 띠의 글이 3초 동안 '통화 끝나고 깔 수 있어'로 바뀌고 '지금 설치'가 그동안 막혀요. 그 뒤 #update-ready | `installUpdate()` = `busy` |
| SCR-001#update-failed | 띠에 '설치하지 못했어. 나중에 다시 해 볼게'와 '다시 설치' 단추. 앱은 조용할 때 다시 해요(SPEC-294) | `installUpdate()` = `failed`, 또는 `marongupdate` 이벤트 뒤 `updateState()`가 `ready`이고 마지막 결과가 실패 |
| SCR-001#update-off | 띠에 '자동 업데이트 꺼짐 · 켜 두면 새 버전이 저절로 깔려'와 '켜기' 단추. 받아 둔 새 버전이 있으면 이 띠 대신 #update-ready예요 | `updateState()` = `none`, `installUpdates` = false |
| SCR-001#update-none | 띠가 없어요. 브라우저로 연 통화 홈, 0.3.2 이하 앱(연결 `version` 2 이하), 안드로이드 8 미만, 받아 둔 버전이 없고 자동 업데이트가 켜짐 | 연결 없음, `version` < 3, 또는 `none`과 `installUpdates` = true(REQ-561) |

- 읽는 때: 통화 홈을 그릴 때 API-001과 함께 앱 연결을 읽어요(연결은 폰 안이라 바로 답해요. 500ms 안에 답이 없으면 #update-none으로 그림). #loading이 #normal로 바뀔 때 띠가 이미 정해져 있어서, 띠가 늦게 나타나 통화 단추가 밀리는 일이 없어요. 앱으로 돌아올 때(`visibilitychange`)와 `marongupdate` 이벤트 때 다시 읽어요. 이때 띠가 새로 생기면 위에서 아래로 200ms 펼쳐요(움직임 줄이기 설정이면 바로).
- 다른 상태와 함께: #in-call·#active-elsewhere(통화 중)에는 띠를 숨겨요(통화가 먼저이고 '지금 설치'를 누를 수 없음). #budget·#daily-limit·#error·#permission에서는 띠가 보여요(통화를 못 걸어도 업데이트는 할 수 있음).
- 문구는 마롱이 말투(반말)이고, 띠의 첫 글 '새 버전 준비됨 · 지금 설치'와 '자동 업데이트 켜기'는 동희님이 고른 글(D129·D130)을 그대로 나눠 썼어요. 버전 이름은 괄호에 작게.
- 색·글꼴·간격은 지금 홈 카드와 SCR-109의 단추 토큰을 써요. 새 토큰은 없어요(09 단계 바뀌지 않음).
- 경우의 종류: 반복(누르면 단추가 바로 막힘), 바깥 서비스(안드로이드 설치 실패 → #update-failed), 데이터 노출(버전 이름만, 릴리스 노트는 보이지 않음 REQ-554), 접근(브라우저와 옛 앱에는 없음).
- 폭과 테마: 360\~430px 세로, 낮·밤 둘 다. 360px에서 글과 단추가 한 줄에 안 들어가면 단추가 글 아래로 내려가요.
- 글 대화(SCR-107)에도 같은 띠를 둬요(D131). 놓는 자리와 다른 상태와의 관계는 아래 'SCR-107 글 대화의 업데이트 배너' 절이에요.

바뀐 승인 글(2026-11-17 이 문서):

- 공통 규칙: "사람이 보는 것은 안드로이드가 확인을 요구할 때의 알림(SCR-130)과 처음 한 번 허용하는 메뉴 줄(SCR-109)뿐이에요." → 배너를 더함(D129·D130).
- 공통 규칙: "앱 창이 화면에 떠 있으면 설치를 미루니(REQ-319) 쓰는 도중에 창이 닫히지 않아요." → '지금 설치'를 누른 때만 예외(D128).
- 바뀌지 않는 화면: "통화 홈(SCR-001), 통화 중(SCR-002), 벨 화면(SCR-110), 전화 알림(SCR-111): 바뀌지 않아요." → 통화 홈을 뺌(D129·D130).

## SCR-107 글 대화의 업데이트 배너(2026-11-22)

Purpose: 선톡 알림을 눌러 글 대화로 바로 들어온 친구도 받아 둔 새 버전을 보고 바로 깔게 하고, 자동 업데이트가 꺼져 있으면 거기서 켜게 해요. (FL-148, REQ-560, REQ-561, REQ-321, REQ-325, D131: 동희님 "둔다 ㄱㄱ", Orca 마롱이 Home 채팅 2026-11-22)

바탕 정의는 [call-first.md](call-first.md)의 SCR-107(`/chat/`)과 SCR-112(앱의 글 대화 창)예요. 띠는 앱의 글 대화 창 안에서만 보이고, 브라우저로 연 글 대화에는 없어요(REQ-561). 띠의 여섯 상태와 글, 단추, 누를 때의 결과는 위 SCR-001 배너와 같아요. 다른 것은 놓는 자리와 다른 상태와의 관계뿐이에요.

## 바뀌지 않는 화면

- 통화 중(SCR-002), 벨 화면(SCR-110), 전화 알림(SCR-111): 바뀌지 않아요. 통화 중이거나 벨이 울리는 중에는 설치를 미뤄요(REQ-319). '지금 설치'도 눌리지 않아요(SPEC-441).
- 통화 홈(SCR-001): 2026-11-22부터 바뀌어요(위 'SCR-001 통화 홈의 업데이트 배너' 절).
- 글 대화(SCR-107), 글 대화 창(SCR-112): 메뉴(SCR-109)와 2026-11-22부터의 업데이트 배너(위 'SCR-107 글 대화의 업데이트 배너' 절, D131) 밖은 바뀌지 않아요.
- 관리 도구(`app-release`)는 서버 명령이라 화면이 없어요(FL-146).
