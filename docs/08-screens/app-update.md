# 앱 자동 업데이트가 바꾸는 화면 상태(CTX-021)

08단계 정의예요(2026-11-17, Claude 제안, 검토 대상). 새 화면은 안드로이드 알림 하나(SCR-130)이고, 있는 화면에는 글 대화 메뉴(SCR-109)에 줄 하나가 늘어요([07 사이트맵](../07-sitemap/sitemap.md)). 바탕 정의는 [app-chat.md](../app-chat.md)(SCR-109)예요. 입력: 기능 명세 [app-update.md](../04-functional-spec/app-update.md)(SPEC-284\~302), 계약 [app-update.openapi.yaml](../../api/app-update.openapi.yaml)(API-141, API-142).

공통 규칙:

- 자동 업데이트는 조용히 일어나요. 받기와 설치에는 화면이 없고, 설치가 끝났다는 알림도 없어요(REQ-324, 확인 질문 3의 추천안). 사람이 보는 것은 안드로이드가 확인을 요구할 때의 알림(SCR-130)과 처음 한 번 허용하는 메뉴 줄(SCR-109)뿐이에요.
- 업데이트가 깔리면 안드로이드가 앱을 끝내요. 앱 창이 화면에 떠 있으면 설치를 미루니(REQ-319) 쓰는 도중에 창이 닫히지 않아요. 다음에 열면 새 버전이에요.
- 안드로이드가 그리는 화면(설치 확인 창, '출처를 알 수 없는 앱 설치' 설정)은 우리가 바꾸지 않아요. 문서에는 들어가고 나오는 경로만 적어요.
- 색·글꼴·간격은 지금 글 대화 메뉴의 토큰을 그대로 써요. 새 토큰은 없어요. 화면 공통 기준(토큰, 부품, SCR 번호표, 목업 한 벌)은 '마롱이의 일기 설계하기' 작업이 맡아요(동희님 2026-11-17 12:36 "걔들이랑 합쳐서 작업해야할거같아"). 이 문서의 상태는 그쪽 목업 한 벌에 들어갔어요: [공통 목업 캔버스](https://claude.ai/artifact/CC154gunovJS3tqa8XkpZ9)(2026-11-17 버전 13)의 `C021-109-*` 대지 넷과 `C021-130-notification`. #update-none은 줄이 없는 상태라 그리지 않았어요.
- 폭은 세로 휴대폰 360\~430px, 테마는 낮(군밤 크림)·밤(밤하늘) 둘 다예요([README](README.md) 공통 규칙).

## SCR-109 알림 상태(글 대화 메뉴)

Purpose: 자동 업데이트가 켜져 있는지 보고, 꺼져 있으면 한 번 켜요. (FL-148, REQ-325, REQ-326)

| Data | Source |
| --- | --- |
| 자동 업데이트를 할 수 있는지(`installUpdates`: true·false, 없으면 줄 없음) | 앱 연결 `MarongPush.state()`(SPEC-301). 서버 API 없음 |

| Action | Result | Failure |
| --- | --- | --- |
| '켜기' 누르기 | 안드로이드의 '출처를 알 수 없는 앱 설치' 설정에서 마롱이 앱 화면이 열려요(`openInstallSettings()`, SPEC-301). 친구가 허용을 켜고 돌아오면(`resumed`) 줄을 다시 읽어 '켜짐'으로 바뀌어요(SPEC-300) | 그 설정 화면이 없는 폰 → 앱 정보 화면이 열려요(SPEC-301). 허용을 켜지 않고 돌아오면 '꺼짐' 그대로 |

| State | What the user sees and can do | From responses |
| --- | --- | --- |
| SCR-109#update-on | 메뉴의 알림 상태 줄들 아래에 '자동 업데이트: 켜짐' 한 줄. 단추 없음 | `MarongPush.state().installUpdates` = true |
| SCR-109#update-off | '자동 업데이트: 꺼짐 · 켜 두면 새 버전이 저절로 깔려'와 그 오른쪽(좁으면 아래) '켜기' 단추. 단추는 같은 메뉴의 '전체 화면 알림 켜기'(SPEC-140)와 같은 모양·크기(누르는 높이 44px 이상) | `installUpdates` = false |
| SCR-109#update-none | 자동 업데이트 줄이 없어요. 브라우저로 연 글 대화, 0.2.1 앱, 안드로이드 8 미만 | `MarongPush` 없음, 또는 `installUpdates` 칸 없음(REQ-326) |

- 읽는 동안(`state()`를 기다리는 동안)은 줄을 그리지 않아요. 지금 메뉴의 다른 앱 줄과 같아요. 줄이 늦게 나타나도 위의 줄이 밀리지 않게 메뉴 맨 아래에 둬요.
- 문구는 마롱이 말투(반말)예요. 지금 메뉴의 '알림은 마롱이 앱에서 받을 수 있어'와 맞췄어요.
- 확인 질문 2의 추천안(메뉴 줄 + 0.2.2 설치 안내에 한 줄)이에요. 0.2.2 설치 안내의 한 줄은 'GPT 인계'의 설치 안내에 적어요([10 WBS](../10-wbs/app-update.md)).

## SCR-130 앱 업데이트 알림(안드로이드 알림)

Purpose: 안드로이드가 사람의 확인을 요구할 때(안드로이드 12 미만, 허용이 꺼짐, 그 밖의 이유) 한 번 알리고, 누르면 확인 창으로 가요. (FL-148, REQ-321)

| Data | Source |
| --- | --- |
| 버전 이름 | API-141#200의 `versionName`(앱이 받아 둔 릴리스, SPEC 3.4 `release`) |
| 확인 창으로 가는 인텐트 | 설치 세션 결과의 `EXTRA_INTENT`(SPEC-297) |

| Action | Result | Failure |
| --- | --- | --- |
| 알림 누르기 | 알림이 사라지고 안드로이드의 업데이트 확인 창이 열려요. 허용이 꺼져 있으면 안드로이드가 먼저 '출처를 알 수 없는 앱 설치' 허용 화면을 보여 줘요. '업데이트'를 누르면 설치돼요 | 확인 창에서 취소 → 아무 일 없음. 같은 버전으로 알림을 다시 띄우지 않고, 다음 확인 차례에 설치를 다시 요청해요(SPEC-296) |
| 알림 밀어서 지우기 | 사라져요 | 같은 버전으로는 다시 띄우지 않아요 |

| State | What the user sees and can do | From responses |
| --- | --- | --- |
| SCR-130#shown | 알림 서랍에 채널 '앱 업데이트'(소리·진동 없음, 중요도 낮음). 제목 '마롱이 앱 새 버전이 있어요', 본문 '눌러서 업데이트해 줘. (0.2.3)'. 앱 아이콘은 지금 알림과 같은 작은 아이콘 | API-141#200, 설치 결과 `STATUS_PENDING_USER_ACTION` |
| SCR-130#locked | 잠금 화면에는 공개 버전 '마롱이 앱 새 버전'만 보여요(`VISIBILITY_PRIVATE`) | 같음 |
| SCR-130#none | 알림이 없어요. 알림 권한이 꺼져 있거나 그 버전으로 이미 띄움. 다음에 앱 창을 열 때 설치가 다시 요청돼요 | 같음, 또는 SPEC 3.4 `notified` = 그 버전 코드 |

- 이 알림은 마롱이 말(앱 알림 SCR-108)과 다른 채널이라, 친구가 '마롱이 말' 알림을 꺼도 업데이트 알림은 따로 켜고 끌 수 있어요.
- 글은 [기능 명세 3.3](../04-functional-spec/app-update.md#33-알림-글scr-130)이 원본이에요.

## 바뀌지 않는 화면

- 통화 홈(SCR-001), 통화 중(SCR-002), 벨 화면(SCR-110), 전화 알림(SCR-111): 바뀌지 않아요. 통화 중이거나 벨이 울리는 중에는 설치를 미뤄요(REQ-319).
- 글 대화(SCR-107), 글 대화 창(SCR-112): 메뉴(SCR-109) 밖은 바뀌지 않아요.
- 관리 도구(`app-release`)는 서버 명령이라 화면이 없어요(FL-146).
