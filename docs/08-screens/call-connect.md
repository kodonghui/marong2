# 통화 연결 속도와 무음 고치기: 화면 상태

상태: 초안(2026-11-21 16시대 KST, Claude, corthex 0.12.x). 새 화면은 없어요. 통화 화면 SCR-002(앱에서는 통화 창 SCR-101 안의 같은 웹)에서 언제 무엇이 보이는지만 바뀌어요. 문구는 모두 지금 `tools/vertex_live/static/app.js`에 있는 것이고, 새로 지은 문구는 없어요. 07 사이트맵과 09 목업은 바뀌지 않아요(새 화면·새 그림 없음, 디자인 토큰 그대로).
입력: [기능 명세](../04-functional-spec/call-connect.md) SPEC-401·402·404, 흐름 FL-180·181.

## SCR-002 통화 중(바뀜)

| State | What the user sees | From |
| --- | --- | --- |
| SCR-002#preparing(새 상태 이름, 동작 고침) | 처음부터 그 시각에 맞는 테마(서버가 `data-theme`를 정해 내려줌)와 기본 글 '잠깐만, 통화할 준비를 하고 있어.'. 화면 코드가 LiveKit 스크립트를 기다리지 않아서 이 상태는 짧아져요. 지금은 LiveKit 619KB를 받는 동안 낮에도 밤 테마로 머물러요(BUG-108) | SPEC-401 |
| SCR-002#connecting(그대로, 지금 화면 문구) | '마롱이를 부르고 있어…'. 마이크·WebRTC·통화 서버 연결이 이 상태에서 함께 돌아요 | SPEC-402 |
| SCR-002#tap-to-hear(새 상태 이름, 지금 문구, 쓰는 때가 늘어남) | '화면을 한 번 눌러 줘. 바로 이어질게.'. 지금은 자동 받기 뒤 2초가 지나도 오디오 엔진이 멈춰 있을 때만 보여요. 앞으로는 LiveKit이 재생할 수 없다고 알릴 때(`canPlaybackAudio=false`)와 `startAudio()`가 실패할 때도 보여요. 누르면 사라지고 소리가 나요 | SPEC-404 ⑤ |
| SCR-002#sound-switching(새 상태 이름, 지금 문구, 쓰는 때가 늘어남) | '소리 연결을 바꾸고 있어. 통화는 계속 이어갈게.'. 지금은 WebRTC가 끊기거나 소리가 오지 않을 때 보여요. 앞으로는 소리가 왔는데 재생되지 않을 때(`rtc_silent`)도 보여요. 첫 PCM 소리가 재생되거나 3초가 지나면 원래 상태 글로 돌아가요 | SPEC-404 ③ |

- 얼굴 입: WebRTC로 받는 동안 입은 지금처럼 받은 소리의 크기로 움직여요. 재생 확인(SPEC-404)이 따로 있어서, 입은 움직이는데 소리가 없는 상태가 2초를 넘기지 않아요.
- 앱의 글 대화 칸(자막 포함)은 지금처럼 앱에서 숨겨요(D20, [app-chat.md](../app-chat.md) SPEC-145). 이 고침과 관계없어요.
