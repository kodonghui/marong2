# 선 전화·그림 화두가 바꾸는 화면 상태(CTX-020)

08단계 정의예요(2026-11-16, Claude 제안, 검토 대상). 새 화면은 없고 있는 화면에 상태가 늘어요([07 사이트맵](../07-sitemap/sitemap.md)). 통화 중 화면의 그림 카드는 [SCR-002](SCR-002.md)의 `SCR-002#topic-card`에 있고, 이 문서는 앱 화면(바탕 정의는 [app-chat.md](../app-chat.md), [app-ring.md](../app-ring.md))과 디스코드 DM에서 바뀌는 것을 적어요. 와이어프레임은 [wireframes-call-first.html](wireframes-call-first.html), 09단계 목업 후보와 추천은 [call-first-candidates.md](../../design/call-first-candidates.md)(목업 페이지 [선 전화·그림 화두 목업](https://claude.ai/artifact/UQYxaGXQ72wGRSWv5YuU8x))이에요. 입력: 기능 명세 [call-first.md](../04-functional-spec/call-first.md)(SPEC-260\~283), 계약 [call-first.openapi.yaml](../../api/call-first.openapi.yaml)(API-140)과 [app-chat.openapi.yaml](../../api/app-chat.openapi.yaml) 0.3.0-draft.

공통 규칙:

- 잠금 화면에 보일 수 있는 글(앱 알림, 전화 알림, 벨 화면)에는 그림의 알림 미리보기 한 줄(TERM-091)과 정해진 말('마롱이가 먼저 걸었어요', '전화했는데 바빴나 봐! 📞')만 써요. 화두 글 전체와 그림은 글 대화를 열어야 보여요(SPEC-272, SPEC-281). 알림 미리보기 한 줄은 마롱이 말투(반말, 1인칭)예요. 예: "나 털모자 샀다!"
- 그림은 512×512 WebP예요. 글 대화에서는 정사각형(240px, 모서리 둥글게), 통화 화면에서는 얼굴 원 안(원으로 잘림)에 보여요(09 추천 A). 그림 안에는 글자가 없어서 대체 글이 그림 설명을 맡아요: 글 대화는 `picture.alt`, 통화 화면은 그림 제목(SPEC-269, SPEC-274).
- 그림을 기다리는 동안 같은 크기의 빈 칸을 먼저 두어 글이 밀리지 않아요. 못 받으면(API-140#404, API-140#default, 네트워크) 그 칸을 지우고 글은 그대로예요. 다시 시도하지 않아요.
- 폭은 세로 휴대폰 360\~430px, 테마는 낮(군밤 크림)·밤(밤하늘) 둘 다예요([README](README.md) 공통 규칙). 움직임 줄이기를 켜면 카드가 움직임 없이 나타나고 사라져요.

## SCR-107 글 대화(`/chat/`)와 SCR-112 글 대화 창(앱)

Purpose: 마롱이가 먼저 꺼낸 그림 화두를 그림과 함께 읽고 답해요. 못 받은 선 전화 뒤의 말도 여기서 봐요. (FL-141, FL-143, FL-144)

| Data | Source |
| --- | --- |
| 마롱이 말의 그림 주소와 설명(`picture.src`, `picture.alt`) | API-102, API-104(`Message.picture`, 0.3.0) |
| 그림 파일 | API-140 |
| 말 종류 `hello`(태그 '먼저 건 전화'), 그림 화두 글은 지금처럼 `proactive`(태그 '먼저 톡') | API-102, API-104(`Message.kind`) |

| Action | Result | Failure |
| --- | --- | --- |
| 끄기·켜기 말 보내기("먼저 전화하지 마", "그림 보내 줘" 등, 기능 명세 3.7) | 보통 말 보내기(API-103)와 같고, 마롱이가 모델 없이 정한 답을 해요(SPEC-277) | 설정 저장 실패 → 마롱이 답 "앗, 지금 설정을 못 바꿨어. 조금 뒤에 다시 말해 줘". 보내기 자체의 실패는 지금 SCR-107 규칙 그대로 |

그림을 누르는 동작(크게 보기)은 두지 않아요. 이번 범위 밖이에요.

| State | What the user sees and can do | From responses |
| --- | --- | --- |
| SCR-107#picture | 마롱이 말 위에 그림(240×240, 둥근 모서리, 대체 글 `picture.alt`), 그 아래 말풍선 글, 그 아래 태그 '먼저 톡'과 시각. 답은 아래 입력 칸에서 평소처럼 | API-102#200·API-104#200(`picture` 있음), API-140#200 |
| SCR-107#picture-loading | 그림 자리에 같은 크기의 빈 칸(말풍선과 같은 바탕색). 글과 태그는 이미 보여요 | (API-140 요청 중) |
| SCR-107#picture-missing | 그림 칸이 없어지고 글만 남아요(보통 마롱이 말과 같은 모양). 오류 문구는 없어요 | API-140#404, API-140#default, 네트워크 없음 |
| SCR-107#hello | 못 받은 선 전화 뒤의 말: 그림(그림 화두가 켜져 있을 때)과 말풍선 "전화했는데 바빴나 봐!", 첫마디 예시, 되묻는 질문(빈 줄로 나뉨), 태그 '먼저 건 전화' | API-102#200·API-104#200(`kind: hello`) |

- 그 밖의 상태(불러오는 중, 첫 대화, 보내는 중, 못 보냄, 다시 연결하는 중, 로그인 필요, 쓸 수 없는 계정, 디스코드 DM 먼저, 너무 많이 보냄)는 [app-chat.md](../app-chat.md) 7절 그대로예요. 새 응답 코드는 없어요.
- 긴 글: 그림 화두 글은 400자까지(SPEC-271)라 말풍선이 길어질 수 있어요. 그림 폭(240px)은 360px 화면에서 얼굴(30px)과 여백을 빼도 들어가요(말풍선 최대 폭보다 좁음).
- 옛 화면: 화면 파일은 서버와 같이 바뀌고 `no-store`라, 새로 불러오면 바로 그림이 보여요. 캐시에 남은 옛 `chat.js`는 `picture`를 읽지 않아 글만, `hello`에 태그 없이 보여요(깨지지 않음).

## SCR-108 앱 알림

Purpose: 마롱이가 그림 화두를 보냈거나 선 전화를 못 받았다는 것을 잠금 화면에서도 괜찮은 한 줄로 알려요. (FL-141, FL-143)

| State | What the user sees and can do | From |
| --- | --- | --- |
| SCR-108#picture-topic | 채널 '마롱이 톡', 제목 '마롱이', 본문은 그림의 알림 미리보기 한 줄(예: "나 닭꼬치 먹는 중 🍢"). 그림과 글 전체는 알림에 없어요. 누르면 SCR-107(앱은 SCR-112) | 봇의 앱 알림(D18, SPEC-272) |
| SCR-108#hello-missed | 채널 '마롱이 톡', 제목 '마롱이', 본문 "전화했는데 바빴나 봐! 📞". 누르면 SCR-107(통화 화면이 아님) | SPEC-270 |

알림을 못 보내면 디스코드 DM으로 가요(D18). 이 화면에 오류 상태는 없어요.

## SCR-110 벨 화면(앱 0.2.2, `RingActivity`)

Purpose: 마롱이가 약속 없이 먼저 건 전화라는 것과 무슨 얘기를 하고 싶은지 한 줄로 알아보고 받거나 거절해요. (FL-142)

| Data | Source |
| --- | --- |
| 벨 이유 `reason`, 알림 미리보기 한 줄 `line` | FCM 벨 메시지 `data`(`RingPushData`, API 계약 3번) |

| Action | Result | Failure |
| --- | --- | --- |
| 받기 | 통화 창이 `/?ring=<id>`로 바로 통화를 시작해요(지금 약속 전화와 같음, SCR-002#topic-card로 이어짐) | 지금 규칙 그대로(시간이 지났으면 보통 통화) |
| 거절 | 화면이 닫혀요. 서버에 알리지 않아서 5분 뒤 못 받음과 같아요(FL-143) | 없음 |

| State | What the user sees and can do | From |
| --- | --- | --- |
| SCR-110#hello | 얼굴(01), '마롱이', 둘째 줄 '마롱이가 먼저 걸었어요', 셋째 줄 `line`(두 줄까지, 넘으면 말줄임), 받기·거절 | `reason: "hello"`, `line`이 1\~30자이고 줄바꿈 없음 |
| SCR-110#hello-no-line | SCR-110#hello에서 셋째 줄만 없음 | `reason: "hello"`, `line` 없음이나 규칙 밖 |
| SCR-110#ringing | 지금 그대로 '약속한 전화예요' | `reason` 없음, `promise`, 모르는 값 |

이 화면은 API를 부르지 않고 벨 메시지에 다 들어 있어서 불러오는 중·빈·오류·권한·오래된 상태가 없어요. 잠금 화면 전체 화면 권한이 꺼져 있으면 SCR-111의 위에 뜨는 알림으로 와요(지금 규칙).

## SCR-111 전화 알림(앱 0.2.2)

| State | What the user sees and can do | From |
| --- | --- | --- |
| SCR-111#hello | 제목 '마롱이', 글 '마롱이가 먼저 걸었어요 · {line}'(`line`이 없거나 규칙 밖이면 '마롱이가 먼저 걸었어요'), 받기·거절. 잠금 화면에도 같은 글이에요 | `reason: "hello"` |
| SCR-111#channel | '마롱이 전화' 채널 설명: "마롱이가 거는 전화예요(약속한 전화와 먼저 거는 전화). 폰 벨소리로 울려요." | SPEC-267 |

못 받은 선 전화의 말은 지금 SCR-111의 '못 받은 전화 한마디'(누르면 통화 화면)가 아니라 SCR-108#hello-missed(누르면 글 대화)로 가요. 약속 전화의 못 받은 한마디는 그대로예요.

## 디스코드 DM(바깥, 디스코드가 그림)

| 경우 | 친구가 보는 것 | From |
| --- | --- | --- |
| 그림 화두 글 | 첫 말에 그림 파일 `marong-<이름>.webp`가 붙고, 다음 말들은 지금 선톡처럼 몇 초 간격으로 와요 | SPEC-273 |
| 못 받은 선 전화(앱 알림이 안 될 때) | "전화했는데 바빴나 봐!"로 시작하는 말들, 그림 화두가 켜져 있으면 첫 말에 그림 | SPEC-270 |
| 끄기·켜기 | 친구의 말에 마롱이가 정한 답 | SPEC-277 |

디스코드의 잠금 화면 알림은 디스코드 앱이 첫 말을 보여 줘요. 그래서 첫 말은 그림의 첫마디 예시처럼 가벼운 말이에요(SPEC-271, AI-20).

## 경우의 종류

| Kind | 화면에서 |
| --- | --- |
| Access | 그림 주소는 Access 뒤 같은 주소라 로그인한 사람만 받아요. 다른 친구의 말은 보이지 않아요(지금 SCR-107 규칙) |
| Input | 끄기·켜기 말은 보통 말로 보내져요. 맞지 않는 말은 보통 대화예요 |
| Target | 없는 그림(API-140#404) → SCR-107#picture-missing, 통화 카드 없음 |
| State changes | 설정을 바꾼 뒤 다음 선톡 차례부터 달라져요. 화면에 바로 바뀌는 것은 없어요 |
| Repeats | 같은 벨 id의 벨은 한 번만 울려요(앱 벨 규칙). 같은 말을 다시 보내면 같은 답 |
| Concurrency | 해당 없음(읽기만) |
| Limits | 하루·한 주 화두 횟수는 화면에 보이지 않아요 |
| Outside services | FCM 실패는 서버가 그림 화두 글로 바꿔요(SPEC-266). 그림 서버 실패는 SCR-107#picture-missing |
| Data exposure | 잠금 화면에는 미리보기 한 줄과 정해진 말만. 벨 메시지에는 벨 id, 이유, 한 줄만 |
| Empty and streamed answers | 그림이 없는 화두 글(그림 화두가 꺼진 선 전화 뒤의 말)은 보통 말풍선 |
| Screen states | 와이어프레임: 360px과 430px, 위의 모든 상태 |
| AI answers | 그림 화두 글은 모델이 쓰고 서버가 확인해요(400자, 마지막에 물음표). 실패하면 그림의 첫마디 예시와 되묻는 질문 그대로(SPEC-271) |
