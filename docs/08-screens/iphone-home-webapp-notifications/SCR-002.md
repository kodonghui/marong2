# SCR-002 통화 중 · 알림 준비와 같은 통화로 복귀

08단계 초안 · FL-225·226·227 · SPEC-546·548·550~553

별도 선택에서 시작한 통화의 준비를 알리고, 복구 가능한 같은 클라이언트의 연결만 기존 통화로 되돌립니다.

## 데이터

| 표시하거나 처리하는 값 | 출처와 표시 범위 |
| --- | --- |

## 행동과 결과

| 행동 | 결과 | 실패·취소 |
| --- | --- | --- |
| 기존 아이폰 창에서 통화 연결 | API-317의 준비 프레임 검증 후 같은 통화를 연동합니다. 101은 준비이며 양방향 오디오 성공은 아직 확인하지 않습니다. | 인증이나 연결을 확인할 수 없으면 #notice-call-check로 전환합니다. 자동 일반 통화 또는 다른 클라이언트의 수락 시도는 없습니다. |
| 잠금 해제·앱 복귀 뒤 다시 연결 | 연결이 살아 있으면 계속 쓰고, 재연결 가능한 같은 클라이언트는 기존 ID로 재연결합니다. | 실제 다른 기기는 기존 SCR-001#call-busy, 복구 불가면 SCR-001#notice-call-ended로 안내합니다. 같은 ID를 확인하지 못하면 성공으로 표시하지 않습니다. |
| ‘연결 확인’ 선택 | 현재 세션과 기존 통화·대상 조건을 읽어 복구 범위를 확인합니다. | 실패는 상태 확인 또는 재인증 안내입니다. 새 통화·수락은 자동 실행하지 않습니다. |
| 기존 음소거·끊기 | 원본의 조작을 사용합니다. 이 창에 연결된 같은 통화만 조작합니다. | 연결이 확인되지 않은 다른 통화에 `stop` 또는 종료 요청을 보내지 않습니다. |

## 화면 규칙

- API-317의 `ready`와 유지된 클라이언트가 확인되면 기존 SCR-002#talking을 사용합니다. 업그레이드 실패의 HTTP 번호를 브라우저가 직접 읽지 못하면 현재 상태를 HTTP로 확인한 뒤 401·403·404·만료·이미 수락 등을 판단합니다.
- 재연결이 기존 통화에 성공하면 동일한 화면과 조작으로 이어집니다. 페이지 또는 통화가 종료된 뒤 사용자가 다시 걸기를 별도로 선택할 수 있습니다. 같은 통화 ID와 양방향 오디오는 실제 기기의 잠금·앱 전환·망 전환 시험에서 확인합니다.
- 통화 자체의 음소거·끊기·말하기·기존 실패는 원본의 같은 상태를 사용합니다. 통화 데이터의 빈 화면은 필요하지 않습니다. 불확실한 연결은 성공/빈 화면 대신 확인 필요 상태입니다.
