# SCR-107 글 대화 · 알림 대상 확인

08단계 초안 · FL-222·223·225·227·228 · SPEC-531~542·545·552·553

알림을 누른 사용자의 계정과 대상만 확인해 같은 방 또는 승인된 통화 홈으로 이어 줍니다.

[변경 상태 와이어프레임](../wireframes-iphone-home-webapp-notifications.draft.html#scr-107) · [응답 대조표](README.md#api-응답-대조표)

## 데이터

| 표시하거나 처리하는 값 | 출처와 표시 범위 |
| --- | --- |
| 알림 진입 참조 | 고정 계약 `/chat/#notice`에서 읽고 주소에서 제거합니다. 복귀 중 단기 상태로만 사용합니다. |
| 대상 확인 결과 | API-314의 `chat`, `ring_ready`, `ring_expired`, `ring_answered`, `ring_unavailable`. 대화와 전화 내용은 현재 접근 확인 이후에만 기존 화면에서 읽습니다. |
| 기존 대화 | API-101~104에 있는 인증·조회·전송 규칙. 현재 계정의 같은 방을 기존 도구로 읽습니다. |
| 해당 답변의 설치별 표시 관찰 | API-316은 현재 설치에서 본 정확한 답변의 단기 신호입니다. 전송 생략 여부는 화면 데이터가 아닙니다. |

## 행동과 결과

| 행동 | 결과 | 실패·취소 |
| --- | --- | --- |
| OS 알림 누르기 | API-314 조회만 수행합니다. 글은 기존 방, 확인한 전화 상태는 SCR-001로 이동합니다. | 401은 SCR-164. 다른 계정·삭제·무효·변조 등은 같은 안전한 접근 불가입니다. 오프라인은 확인 불가입니다. |
| 대상 다시 확인 | 같은 단기 참조로 현재 계정에서 재조회합니다. | 참조가 유실되면 보호된 대상을 복원하지 않고 안전하게 기존 글 대화 진입을 제공합니다. |
| 독립적으로 글 대화 열기 | 참조를 정리한 뒤 기존 SCR-107의 인증과 방 선택을 사용합니다. | 기존 로그인·연결 실패 상태를 사용합니다. |
| 현재 답변 표시·숨김 | 화면이 실제로 보고 있는 답변을 API-316으로 보고할 수 있습니다. | 보고 실패는 대화 표시나 방 기록에 영향이 없습니다. 그 설치가 해당 답변을 본 것으로 간주하지 않습니다. |

화면 글은 검토용 문구입니다.

| --- | --- | --- | --- | --- | --- | --- |
| <a id="notice-loading"></a>`SCR-107#notice-loading` | loading | 알림을 확인하고 있어 | 지금 로그인과 알림을 열 수 있는지 확인 중이야. | — | 최초 외부 진입만 제목에 초점. 재확인은 기존 버튼 위치를 유지하고 진행을 한 번 읽습니다. | API-314 요청 중 |
| <a id="notice-room"></a>`SCR-107#notice-room` | normal | 글 대화 | 확인된 이 대화방의 글을 보여 줘요. 원래 대화 목록과 쓰기 흐름을 사용해요. | 메시지 입력 | 기존 방 제목 또는 메시지 위치 안내. 입력 칸으로 자동 이동해 키보드를 열지 않습니다. | API-314#200 chat 뒤 기존 API-102 |
| <a id="notice-denied"></a>`SCR-107#notice-denied` | permission | 이 알림을 열 수 없어 | 글 대화로 돌아가 다시 확인할 수 있어. | 글 대화로 | 제목으로 이동하고 읽습니다. 계정·대상의 존재 여부는 문구에 넣지 않습니다. | API-314#400 invalid_input, #403 cross_site 또는 not_allowed, #404 not_found |
| <a id="notice-unavailable"></a>`SCR-107#notice-unavailable` | error | 아직 알림을 확인할 수 없어 | 연결을 확인한 뒤 다시 시도해 줘. 확인 전에는 알림 내용을 열 수 없어. | 다시 확인 · 글 대화로 | 오류 제목, 다음은 재확인. 기존 알림 내용이나 캐시된 대화는 이 상태에서 표시하지 않습니다. | API-314#503, default, 오프라인 또는 응답 유실 |
| <a id="notice-rate-limited"></a>`SCR-107#notice-rate-limited` | error | 잠시 뒤 알림을 확인해 줘 | 안내된 대기 시간이 지나면 알림을 다시 확인할 수 있어. | 다시 확인 (비활성) · 글 대화로 | 대기 상태를 한 번 읽고 분당·초당 재안내 없이 버튼만 갱신합니다. | API-314#429 request_limit 및 Retry-After |

## 화면 규칙

- 전화 상태는 사용자에게 대상 접근 권한이 확인됐을 때만 SCR-001로 넘깁니다. 조회만으로 방 쓰기, 수락, 일반 통화, 마이크가 시작되지 않습니다.
- 알림 대상의 404는 계정 불일치·대상 삭제·존재하지 않음·검증 실패 중 어느 것인지 구별할 수 없어야 합니다. 형식·출처 오류도 보호 정보 없이 같은 안전한 화면을 사용합니다.
- 일반 Safari와 Android에 이미 있는 직접 `pendingRing` 받기, 빈 대화·전송 중·실패·안 읽은 글 표시는 기존 정의를 참조합니다.
