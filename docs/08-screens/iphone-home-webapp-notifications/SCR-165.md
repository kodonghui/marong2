# SCR-165 내 마롱이 · 알림 설정

08단계 초안 · FL-220·221·227 · SPEC-520~530·552·554

아이폰 사용자가 기존 경로에서 홈 화면 추가 순서를 확인하고, 지원되는 설치에서 자기 기기의 수신을 선택하거나 해제합니다.

## 데이터

| 표시하거나 처리하는 값 | 출처와 표시 범위 |
| --- | --- |
| 일반 Safari, 홈 화면 웹앱, 지원 여부, 현재 허용 | 클라이언트 실행 형태·기능 감지와 OS 권한. 확정 가능한 미지원과 일시 확인 실패를 분리합니다. |
| 설치별 구독 상태 | API-310#200의 상태와 현재 OS 권한을 같이 확인합니다. 공개 VAPID 키와 단기 토큰은 처리에만 사용합니다. |
| 현재 변경 결과 | API-311의 선택 토큰, API-312의 현재 등록, API-313의 철회·미등록. 이전 동의·버전 또는 주소 충돌은 API 상태만 읽습니다. |
| 로그인 종료 | 기존 API-215에서 성공하면 기존 로그인으로 갑니다. 실패는 완료로 표시하지 않습니다. |

## 행동과 결과

| 행동 | 결과 | 실패·취소 |
| --- | --- | --- |
| 웹 알림 안내 보기 | 일반 Safari에서 공유 메뉴, 홈 화면 추가와 이후 실행 순서를 안내합니다. | OS 실행 취소나 미설치에서는 기존 글 대화·통화를 이용합니다. 권한 요청 0회입니다. |
| 지원되는 웹앱에서 ‘알림 켜기’ 또는 ‘다시 켜기’ | 사용자의 직접 선택 뒤 OS 허용·구독과 API-311·312를 확인합니다. 허용과 등록이 둘 다 유효해야 수신 가능입니다. | 팝업을 닫으면 준비 전 상태로 돌아갑니다. 거부는 OS 설정만 안내하고 자동으로 다시 묻지 않습니다. |
| 현재 설치의 알림 끄기 | API-311·313 완료 뒤 이 설치의 수신 해제를 표시합니다. | 응답 유실·충돌에서는 상태를 다시 확인합니다. 다른 설치의 구독을 읽거나 바꾸지 않습니다. |
| 설정 다시 보기 | API-310으로 OS 권한과 현재 서버 상태를 함께 확인합니다. 필요한 자동 갱신만 현재 동의 안에서 처리합니다. | 철회·구독 영구 무효 뒤에는 자동 갱신으로 알림을 복원하지 않습니다. |
| 기존 로그아웃 | API-215 성공에서 SCR-164 기존 로그인으로 갑니다. | 기존 오류 상태를 따릅니다. 로그인 복귀나 OS 허용을 새로운 동의로 처리하지 않습니다. |

## 화면 규칙

- OS 공유 메뉴, 시스템 권한 팝업의 내부 조작과 아이폰 설정 화면은 OS가 소유합니다. 앱 와이어프레임은 이들을 호출하기 전과 돌아온 뒤만 보여 줍니다.
- API-310#200 active만으로 ‘수신 가능’을 표시하지 않습니다. OS 권한이 꺼져 있거나 확인할 수 없으면 각각 권한 또는 확인 불가 상태입니다. 401은 SCR-164#notification-settings-login입니다.
- 일반 Safari는 #ios-guide를 사용합니다. 기존 아이콘의 시작 경로는 `/chat/`이며 삭제·재설치는 요구하지 않습니다. iOS 16.4 이상 일반 Web Push, 18.4 이상 선언형 폴백은 실기기 검증 후보입니다.
- 빈 상태는 미등록에 해당합니다. 사용자가 입력하는 구독 폼·본문·AI 응답은 없습니다. 알림 수명이나 전화 기한 종료로 설정 상태를 바꾸지 않습니다.
