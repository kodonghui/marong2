## 2. `/chat/persona/` 화면의 공통 규칙

[08 화면 정의 README](README.md)의 공통 규칙과 `/chat/` 아래 화면 규칙(일기 스레드 PR #25)에 더해요.

- 문: 글 대화와 같은 Access 앱이에요. 봇이 `Cf-Access-Jwt-Assertion`으로 통화 친구와 그 친구(`call.callers.friend_id`)를 찾고, 모든 값을 그 친구 것으로만 읽고 바꿔요(API 계약 머리). 친구 약속·맞춤형 지침은 `MARONG_FRIEND_CARD`, 기억 화면은 기억 기능(`on`)이 켜져 있을 때만 열려요.
- 머리: 왼쪽 돌아가는 버튼(48px, 글 '글 대화' 또는 '친구 약속'), 가운데 제목(굵게), 아래 `line` 1px. 앱 창의 뒤로 가기는 창을 닫으니까 머리 버튼이 유일한 돌아가는 경로예요.
- 401: 쓰던 글(규칙 칸, 지침 칸)을 `sessionStorage`에 남기고 페이지를 새로 불러 Access 로그인으로 가요. 돌아오면 그 글을 칸에 다시 넣고 지워요.
- 403 `not_allowed`: 안내 화면 "이 계정으로는 열 수 없어"와 '글 대화로'. `feature_off`: 안내 화면 "이건 아직 준비 중이야"와 '글 대화로'. 둘 다 다시 시도하지 않아요. `cross_site`: 그 동작 옆 "이 화면에서 다시 해 줘", 저절로 다시 보내지 않아요.
- 503 `db_unavailable`: 화면을 그대로 두고 위에 띠 "잠깐 문제가 생겼어. 조금 있다가 다시 해 줘". 불러오기는 5초부터 30초까지 늘려 가며 다시 해요. 쓰기는 값을 응답 전으로 되돌리고 띠만 보여요(저절로 다시 보내지 않음).
- `default`·네트워크 없음·시간 넘김(10초, 맞춤형 지침 저장은 15초): 불러오기는 안내 화면 "잠깐 문제가 생겼어. 다시 해 볼래?"와 '다시 해 볼게', 추적 id(`caption`). 쓰기는 그 동작 옆 짧은 말과 '다시 해 볼게'.
- 반복: 요청이 도는 동안 그 버튼·칩 그룹을 막아요. 같은 값은 서버도 200으로 그대로 둬요(계약 2).
- 지금 값: 페이지가 다시 보일 때(`visibilitychange`, 앱으로 돌아옴) 그 화면의 읽기 API를 다시 불러요. 대화에서 바꾼 값(SPEC-195·198·202)이 그때 보여요. 쓰던 칸은 덮어쓰지 않아요(SCR-121#stale).
- 친구 글(규칙, 지침, 기억, 인용)은 `textContent`로만 넣어요.
- 테마: 한국 시각 08:00\~20:00 직전 군밤 크림, 그 밖 밤하늘. 앱 모양(`design/README.md` 2절)이에요.
- 폭: 360\~430px 세로. 넓은 화면은 글 대화처럼 가운데 폰 틀(`backdrop`, `panel-shadow`)이에요.
- 고르기 칩: 한 그룹이 `role="radiogroup"`, 칩마다 `role="radio"`, 높이 48px(`size.touch-min`), 둥근 모서리 `radius.full`. 고른 칩은 글로도 '골랐어'가 읽혀요(`aria-checked`).
- 크기 토큰(화면 공통 기준 `design/README.md` 3·4절, 2026-11-17 일기 스레드와 맞춤): 새 페이지(SCR-120\~122)의 글 버튼 테두리·띠·확인 줄은 `radius.sm`, 칩은 `radius.full`, 카드는 `radius.md`. 마롱이 말풍선은 `font-size.bubble` 15px·`radius.bubble` 18px. 글 대화 안의 고르기 카드(SCR-123)는 이미 있는 화면이라 `chat.css` 값을 따라요.
- 움직임 줄이기: 칩·띠·알림 조각의 움직임을 끄고 바로 바꿔요.

## 3. 다른 화면에서 바뀌는 곳

| 화면 | 바뀌는 것 | 근거 |
| --- | --- | --- |
| SCR-107 글 대화(`docs/app-chat.md`) | 머리 오른쪽에 '나' 아이콘 버튼(44px, 같은 줄의 전화·알림·일기장 버튼과 같음, `aria-label` "친구 약속"). 글 대화를 열 때 API-127을 한 번 불러 200일 때만 보여요(일기장 버튼과 같은 방식). 누르면 `/chat/persona/` | 이 절, SPEC-194 |
| SCR-107 글 대화 | 마롱이 말에 `card`가 있으면 말풍선 아래에 고르기 카드(SCR-123) | API-102·104 0.4.0, SPEC-192 |
| SCR-108 앱 알림 | 바뀌지 않아요. 카드가 붙은 말도 알림에는 지금 규칙대로 말의 글만 가고 고르기 칸은 없어요 | `docs/app-chat.md` SCR-108 |
| SCR-112 글 대화 창 | 바뀌지 않아요. 페이지가 봇에서 오니까 카드도 새 chat.js가 그려요(앱 버전과 상관없음) | `docs/app-chat.md` SPEC-124 |

글 대화 머리에는 지금 전화·알림 버튼이 있고 일기장 버튼(PR #25)이 더해져요. '나' 버튼까지 네 개여도 360px에서 한 줄에 들어가요(버튼 44px × 4 + 사이 6px × 3 = 194px, 좌우 여백 32px, '마롱이' 글 약 80px과 사이 10px을 더해 약 316px). 머리 오른쪽 버튼 44px은 화면 공통 기준(PR #25 `design/README.md` 4절 '글 대화 머리 오른쪽 버튼')이고, 48px로 올리는 건 글 대화 전체를 바꿀 때 같이 해요.

## 4. 경우의 종류(네 화면 공통)

| 종류 | 화면이 보이는 것 |
| --- | --- |
| Access | 401은 다시 로그인, 403은 안내 화면(2절). 남의 규칙·기억·카드 id는 404라 '찾지 못했어'와 다시 불러오기 |
| Input | 규칙 길이(호칭·부르는 이름 1\~4자, 주제 2\~20자), 지침 1\~500자는 칸이 먼저 막고, 400이 와도 그 칸 옆 말과 쓴 글 그대로 |
| Target | 이미 지운 규칙·잊은 기억·닫힌 카드 → 404·409 뒤 목록이나 대화를 다시 불러요 |
| State changes | 대화에서 바뀐 값은 화면이 다시 보일 때 보여요. 카드는 다른 곳(디스코드 단추, 카톡 번호)에서 답하면 닫혀요 |
| Repeats | 도는 동안 막음. 같은 카드에 같은 값은 처음 결과(계약 9), 같은 잊기 키는 처음 결과(계약 8) |
| Concurrency | 친구 약속은 나중 쓰기가 이겨요(409 없음). 지침은 쓰던 칸이 있으면 덮지 않고 알려요 |
| Limits | 규칙 종류마다 20개(409 `rule_limit`), 지침 저장 1분에 5번(429, 남은 초) |
| Outside services | 지침 저장의 모델(AI-14) 실패는 503 `ai_unavailable`, 쓴 글 그대로 다시 저장 |
| Data exposure | 근거 메시지 id, 방 이름·키, 위기 상태, 선톡 결과, 민감 종류는 응답에 없어요(API 머리). 기억 화면은 본인에게만 |
| Empty and streamed answers | 약속 없음(SCR-120#none), 지침 없음(SCR-121#empty), 기억 없음(SCR-122#empty). 흐르는 답은 없어요 |
| Screen states | 상태마다 360px·430px 와이어프레임. 긴 약속 문장(200자), 긴 규칙(20자), 긴 기억(80자)과 인용(120자)을 넣어 봤어요 |
| AI answers | 지침의 이해한 내용과 못 지키는 한 줄(AI-14)은 글로만 보여요. 위험할 때 하는 말은 지침으로 바꿀 수 없다는 줄이 늘 있어요(SCR-121) |
