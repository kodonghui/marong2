## GPT 인계 절 형식

WBS 파일 맨 위, 제목 바로 아래에 이 절을 둬요. GPT는 이 절과 거기 적힌 ID만 읽고 시작할 수 있어야 해요.

```markdown
## GPT 인계

- 목표: 한 줄. 동희님 원문이나 그 자리 링크
- 시작: 브랜치 `<브랜치>` 커밋 `<짧은 해시>`에서 새 브랜치 `codex/<패키지>`
- 읽을 것: 파일 경로와 ID 범위(SPEC-·API-·TBL-·SCR-·AI-), 목업 링크. 이 밖의 문서는 읽지 않아도 됨
- 이미 된 것: 커밋이나 참고 패치, 어디까지 믿어도 되는지
- 순서: TASK-xxx → TASK-yyy(같이 해도 되는 것은 묶어 표시)
- 시험 환경: pgserver·Node·Java 21 등. 진짜 모델·유료 API를 불러도 되는지
- 반영: 서버 반영을 하는지. 하면 마이그레이션·파일·켜고 끄는 설정·재시작할 서비스·되돌리기. 앱이면 버전·versionCode·서명
- 하면 안 되는 것: 이 패키지에만 있는 금지(공통 금지는 AGENTS.md)
- 겹치는 파일: 다른 패키지와 같이 고치는 파일과 합치는 순서
- 사람 확인: 구현 뒤 동희님·현경님이 볼 것(TC ID)
- 끝 조건: 모든 TASK의 끝 조건 시험 통과, 그리고 이 패키지에만 있는 조건
- 설계 질문: PR 설명 맨 위 '설계 질문'에 적으면 설계 스레드가 답함
```

TASK 표는 corthex 10단계 형식 그대로 쓰고, Owner는 `GPT`(서명 키가 노트북에만 있는 일은 `GPT(동희님 노트북)`), 끝 조건에는 돌릴 시험 파일이나 명령을 적어요. API를 건드리는 TASK는 그 operation이 나열한 응답마다 시험이 통과해야 끝이에요.
