## 응답 시험

고정 OpenAPI의 응답 코드·예시와 WebSocket 계약을 아래 TASK의 자동 시험에서 직접 대조합니다. 각 실행 결과에는 상태·예시 이름, 공개 응답 스키마, 접근/쓰기 부작용, 사용자 상태 연결을 남깁니다. HTTP 오류는 `application/problem+json`의 `title/status/code/traceId` 및 문서화된 헤더를 검사합니다. 403 공용 응답은 `cross_site`, `not_allowed` 예시를 각각 확인하고 429는 `Retry-After`를 확인합니다. 400·401·404·503·default의 기본 코드도 OpenAPI의 응답 참조대로 검사합니다. ## 출시와 운영 선행 조건

- TASK-583에서 남는 비활성 행·복제·백업·키 및 대상 참조의 보존·파기/회수 기간, 역할과 증거를 별도 계약으로 확정합니다. 전송 수명, 구독 만료, 보존 기간은 각각 검증합니다. 시험에서도 활성 발송 역할 밖에서 복호화가 불가능함을 확인합니다.
- 동시 수락, 로그아웃과 발송 인계, 원문 미표시, 설치별 단일 표시와 실제 양방향 복귀 실패를 발견하면 해당 범위의 출시 결정을 멈춥니다. 승인된 흐름을 구현할 수 없다면 기존 요구의 의미를 바꾸는 안을 먼저 사용자님께 올립니다.
- TASK-582에서 반영 대상과 실행 사본마다 읽기 대조 기준, 새 기능 설정 기본값, DB·파일 백업, 마이그레이션 적용과 재실행, 기능 차단 및 되돌리기, 대화·통화가 없을 때 재시작, 최소 5분 오류 확인과 기능 노출 점검 조건을 문서화합니다. 운영 권한·병합·실제 발송 및 사용자 데이터 정리는 각각 해당 승인 후 진행합니다. [저장소 운영 절차](../../AGENTS.md#서버-반영인계-절에-반영이-들어-있을-때만)
