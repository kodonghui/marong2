# BUG-114 웹 통화 재연결을 다른 기기의 통화로 표시

- 상태 `open` · 심각도 S2 · 우선순위 P1 · 유형 구현 · 원인 11단계
- 발견 운영, 2026-11-24 02:00~02:04 KST, iPhone Safari 웹 통화 두 번. 통화가 끊긴 뒤 통화 중 표시와 함께 ‘다른 기기에서 마롱이랑 통화 중이야’가 보였어요.
- 기준 [SPEC-386 §3.9](../04-functional-spec/unified.md#39-목소리와-동시-통화spec-385-spec-386), [SCR-001#call-busy](../08-screens/unified.md), [TC-468](unified.md). 승인된 명세는 같은 계정과 클라이언트 ID의 재연결을 허용해요. 문서 변경 없음(기존 명세 유지).

## 재현과 근거

1. 합성 계정으로 웹 통화를 열고 첫 `ready`의 통화 ID를 기록해요.
2. 브라우저와 서버 사이 연결을 끊고, 서버 쪽에서 이전 연결의 종료 처리가 끝나기 전에 같은 클라이언트 ID로 다시 연결해요.
3. 기존 코드는 `call_busy`를 반환해요. 화면은 남아 있는 통화 ID로 종료 요청을 보낼 수 있어요. 기존 연결이 정리되면 같은 통화 ID로 돌아와야 해요. 같은 계정의 다른 클라이언트 ID는 `call_busy`여야 해요.

운영의 두 통화는 각각 103.6초와 67.3초에 끝났어요. 마지막 `last_beat_at`에서 종료까지 8.8초와 12.0초가 지났어요. 이 값은 통화·자막 DB의 갱신 시각이며 WebSocket ping/pong 시각은 기록하지 않아요. 통화마다 구간 1개가 `user_hangup`으로 닫혔고, 전송 기록은 `pcm/start`와 `webrtc/start` 각 1개였어요. 마지막 재생 보고의 `context`는 두 건 모두 `running`으로, 끊긴 순간의 상태는 기록되지 않았어요. 해당 시간대 통화 서비스 로그는 0줄이에요. 화면이 보낸 종료 요청과 직접 누른 종료 버튼은 기존 기록에서 구분할 수 없어요. 최초 연결이 끊긴 원인은 미확정이에요.

터널의 `context canceled` 6줄은 첫 통화 시작 이전에 발생했어요. 운영 코드에는 60초 또는 90초에 통화를 종료하는 조건이 없어요. Live 공급자의 일반 연결 한도는 약 10분이며, 공급자 연결이 종료되면 서버는 브라우저 WebSocket을 유지한 채 다시 연결하도록 구현돼 있어요. 화면 잠금, 백그라운드 전환, 오디오 중단, WebSocket·WebRTC의 순간 단절은 당시 기록으로 구분할 수 없어요.

Anthropic 인증은 음성 스트리밍과 별도 통화 기억 정리기에 쓰이지 않아요. 통화 중 상품 읽기 기능은 활성화돼 있고, 이 도구가 호출되면 앱 서버를 통해 Anthropic을 써요. 인증에 실패하면 도구 오류로 처리해요. 해당 시간대 앱 서버에 상품 읽기 기록은 0건이었고, 확인된 401 관련 3줄은 두 번째 통화가 끝난 뒤였어요.

## 시험 누락과 회귀 기준

[TC-468](unified.md)은 다른 기기의 중복 시작과 서버 한도를 확인했어요. 같은 클라이언트가 이전 WebSocket과 겹치는 경우가 빠져 있었어요. TC-643은 이전 연결을 정리하는 동안 세션과 통화 ID가 유지되는지, 실제 다른 기기는 거절하는지, 접속 거절로 종료 신호를 보내는지 확인해요. Windows에서 iPhone WebKit, Android Chrome, 데스크톱 Chromium 프로필로 동일한 연결 단절을 주입하고 실제 기기 확인을 별도로 기록해요.

수정 전 `256c5cf`에서 API 시험의 같은 클라이언트가 `call_busy`를 받았고, Node 시험에서 자동 종료 POST 1건이 발생했어요. 두 Chromium 프로필의 브라우저 시험에서도 같은 실패가 재현됐어요.

수정 `4f340dd`는 같은 클라이언트가 연결되면 이전 서버 세션의 정리가 끝나기를 기다린 뒤 기존 통화 ID로 다시 연결해요. 접속 거절이나 화면 오류는 종료 POST와 `stop` 메시지를 보내지 않아요. 통화 서버 로그에는 연결과 종료 이유, 종료 코드, 경과 시간, 무작위 클라이언트 ID의 앞 8자리만 남겨요. 공급자 재연결 오류와 `goAway`도 같은 앞자리로 대조할 수 있어요.

수정 후 API 시험 통과. Windows의 WebKit·Chromium 프로필 3개에서 각각 통화 ID 유지 1건, 자동 종료 POST 0건, 종료 버튼을 누른 뒤 POST 1건을 확인했어요. Windows WebKit 시험의 오디오는 가짜이고 WebSocket과 화면은 실제 브라우저를 사용했어요. 실제 iPhone·Android의 화면 잠금, 망 전환, 소리 확인은 운영 반영 뒤 검증할 항목이에요.
