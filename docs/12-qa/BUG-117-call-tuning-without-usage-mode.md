## 재현과 회귀 기준

TC-644. 검침 모드가 없는 격리 DB에 다른 값의 구간 설정을 지정하고 가짜 Live 연결을 연다. 기존 코드의 `LiveSession.google_loop()`는 `usage_mode`가 없으면 구간 설정을 읽지 않는다. 구간 이름이 비고 공급자 요청에도 지정한 값이 빠진다. 설정 조회 실패 때는 기본 설정 이름과 값이 적용되어야 한다. 양쪽 모두 검침 설정이 없을 때는 추정 집계가 유지되어야 한다.

TC-173은 검침이 없는 구간의 추정을, TC-176은 검침이 켜진 구간의 설정을 확인했다. 두 조건을 동시에 검증하는 사례가 빠졌다. 원인 단계에서 기존 SPEC-177의 구간 설정과 검침 모드의 결합을 풀며, 기능 명세는 유지한다.

수정 전 제품 코드 `a39fef4`에서 지정 토큰 한도는 768 대신 1,024였고, 기본 구간의 설정 필드가 비었다. `7fe94a4`에 로컬 회귀가 통과했다. 가짜 공급자와 격리 PostgreSQL에서 지정 설정 반영, 설정 없음·시간 초과 시 기본 설정, 종료 구간 추정 세 가지를 확인했다. TC-173~176의 사용량 저장·비용·예산·전환 시험도 통과했다.
