## Gate와 상태: 체크포인트 승인

Gate 열은 2026-11-27 체크포인트에서 승인된 지정이에요([D164](../10-wbs/README.md#결정), PR #140 `c0fced1`). REQ-570·571·572·574~582의 Must와 이를 지키는 승인 SPEC·API 권한 및 오류를 포함한 TC를 `gate`로 지정해요. TC-638은 기존 아이템 기능의 Must REQ-527~529와 REQ-570을 포함하고, 꾸미기 켜진 시험 환경을 사용해요. TC-640·641은 REQ-585가 Should이므로 `non-gate`이며 360px Must인 REQ-581은 TC-637이 따로 검사해요. REQ-583(Could)의 TC-635·636과 REQ-586·587(Should)에 특화된 TC-653·656~658도 `non-gate`로 지정해요. TC-655는 REQ-577 Must인 앱 버전의 앱 지워짐 표시를 포함하므로 `gate`예요. TC-654·659는 Should 기능의 경계도 다루지만 REQ-572 Must인 개요 숫자와 연결되어 `gate`로 지정해요. TC-639는 Must의 운영 반영 확인을 포함해 `gate`로 지정하고 TC-657은 기능 변경 3의 Should 전용 운영 확인으로 `non-gate`예요. SPEC 하나에 여러 우선순위가 섞이면 해당 TC의 Must 부분이 있는지 기준으로 삼았어요.

Status는 `pass`, `fail`, `blocked`, `not run`, `waived` 중 하나예요. 과거 커밋에서 통과한 사례는 원래 결과를 Run evidence에 보존했고, 그것만으로 최신 릴리스 커밋의 통과를 주장하지 않아요. 최신 기준 `9811ad9` 시험의 대응 범위와 미확인 부분, 잠정 집계는 [QA 확인 기록](runs/2026-11-27-admin-review.md#릴리스-게이트-지정과-잠정-집계)에 있어요. `waived`는 사용자님의 개별 결정 없이 쓰지 않아요.

체크포인트 답: gate 21건·non-gate 9건을 승인했고, 리뷰에서 Must인 REQ-577에 맞춰 TC-655를 gate로 정정해 gate 22건·non-gate 8건이에요(D164). 승인된 요구사항·SPEC의 기능과 우선순위는 바뀌지 않아요. TC-639·657의 미확인 부분과 BUG-115는 그대로 남고, 면제·PR 병합·운영 배포·실사용자 릴리스는 승인 범위에 없어요.
