- 관련: SPEC-417, SCR-186#default, TC-543.
- 환경: 2026-11-27 조사 기준 `9811ad9`, 합성 API 응답과 격리 WebKit.
- 재현: 관리자 아이템 화면을 열어요. 승인 화면은 썸네일·id·종류·이름·상태·받은 사람 수·버튼 표인데 기존 화면은 카드이며 처음 세 열이 없어요.
- 원인: 11단계 코드가 승인된 화면과 달라요. 설계 문서는 고치지 않아요.
- 회귀: 기준 `9811ad9`에서 열 검사 실패를 확인하고, 수정 작업본에서 격리 WebKit의 같은 검사 통과를 확인했어요. 저장소 회귀는 `apps/android/test/pet-decor.e2e.cjs`의 TC-543에 있어요.
- 탈출: 기존 TC-543 실행 기록은 일부 화면만 확인하고 전체 통과로 적었어요. 전체 조건을 확인하기 전에는 통과로 적지 않아요.
- 남은 것: Access만 통과한 관리자에서 API-257 썸네일 접근과 승인된 나머지 상태를 확인해야 해요. PR 병합 전이므로 상태는 열림이에요.

- 추가 재현: 기준 `df2406e`에서 TC-543의 거르개, 내리기 확인, 누락 항목의 올리기 단추 숨김, 403 권한 상태 회귀가 각각 실패했어요. 네 조건 모두 원인은 11단계 구현이며 설계 문서 변경은 없어요.
- 인증 설계 질문: SPEC-395는 관리자 로그인 쿠키를 보지 않지만, SPEC-425·API-257은 로그인한 친구만 파일을 읽게 해요. SCR-186 썸네일에서 두 조건을 어떻게 맞출지 결정 전에는 API 인증을 바꾸지 않아요.
