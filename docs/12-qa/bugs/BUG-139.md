# BUG-139 스위치가 꺼진 새 DB에서 기존 옷이 빠짐

2026-11-28 PR #148 코드 리뷰에서 발견했어요. 서울 격리 환경의 임시 Postgres에서 `MARONG_DECOR=1`, `MARONG_DEFAULT_WEAR=0`으로 빈 DB에 카탈로그를 두 번 등록하면 착용 아이템 네 개의 기본 마롱이 레이어가 없다는 이유로 48개 중 44개만 등록됐어요. 그 네 개는 기존 반려동물 상점에서도 받을 수 없었어요.

SPEC-575는 스위치가 꺼지면 기존 동작을 유지하도록 정해요. 원인은 11단계 구현에서 새 레이어 검사를 기존 아이템 자동 등록에 무조건 적용한 것이고, 승인된 문서 변경은 없어요. 레이어가 빠진 목록에서 스위치 0의 자동 등록과 상점 받기를 시험하며, 기본 마롱이 레이어가 필요한 검사는 계속 엄격하고 다른 반려동물 레이어 누락은 계속 거절되는지도 확인해요.

회귀 시험: `tests/test_decor.py`의 `test_bug139_switch_off_seeds_all_existing_items_and_shop`. 수정 전 `e0e103d`에서 기대 48개, 실제 44개로 실패했어요. 수정 후 같은 임시 DB와 가짜 인증 환경에서 48개와 기존 아이템 받기를 확인해요. 병합 전이므로 상태는 `open`이에요.

Stopped by: 자동 등록에 쓰는 검사에서 스위치에 맞는 검증 범위를 명시하고 회귀 시험으로 보장해요. API 형식이나 정적 타입은 해당 스위치와 파일 부재의 조합에서 기존 아이템을 등록해야 하는 실행 시 동작을 보장하지 못해요.
