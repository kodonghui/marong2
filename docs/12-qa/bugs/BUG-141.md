# BUG-141 그림 작업 중 레이어가 복구되거나 바뀌면 차림이 어긋남

2026-11-28 PR #148 네 번째 리뷰에서 발견했어요. 서울 격리 환경에서 모자와 옷이 유효할 때 옷 반응 그림을 대기시킨 다음 모자를 빼고 그림을 시작해 모자 없이 그리게 해요. 완료 확인 전 모자 파일을 복구하면 처음 대기시킨 차림과 현재 차림이 같아 실제 그림이 틀렸는데도 그대로 반환돼요. 같은 아이템 파일이 유효한 다른 그림으로 바뀌는 경우도 식별자만 비교하면 놓쳐요. SPEC-572·574와 D196에 맞는 실제 유효 차림을 비교해야 하며 원인은 11단계 구현이므로 승인 문서 변경은 없어요.

회귀 시험: `tests/test_scene_picture.py`의 `test_bug141_`은 무효에서 복구와 유효한 파일 내용 변경을 가짜 모델과 임시 DB로 확인해요. 병합 전이므로 상태는 `open`이에요.

수정 전 `3ec6be6`에서 무효→복구와 같은 아이템의 유효 파일 변경 두 사례가 각각 잘못된 작업 그림을 반환해 실패했어요. 일기 작업도 `c8ed2c0`의 회귀 시험에서 그리는 도중 파일이 바뀌어도 성공으로 기록해 실패했어요. `20b2818`은 025에 실제 그리기 시작 때 쓴 유효 자리·아이템·파일 SHA-256 기록을 더하고, 임대와 시도 횟수가 같은 작업만 그림 모델을 부르기 전에 기록하게 해요. 완료 뒤 현재 유효 차림과 비교해 다르면 실제로 쓴 바이트를 확인한 겹친 그림을 사용해요. 밤 일기와 다시 그리기도 시작·완료 때 비교하고 변경 시 성공 그림을 쓰지 않으며, 호출 비용은 남겨요. 기본 마롱이 그림 화두는 기존 그림 세트라 새 장면 그림을 만들지 않고, 반려동물 화두·일기는 기존 반려동물 차림 경로라는 점도 대조했어요.

Stopped by: 작업에 실제 그림 지시의 차림과 파일 해시를 고정하고 완료 검증에서 현재 값과 비교하는 구조로 막아요. 같은 ID의 파일 내용은 실행 중 바뀔 수 있어 정적 타입이나 린트만으로 검증할 수 없어요. 임시 Postgres에서 025 두 번과 자료가 있는 상태의 재적용도 통과했어요.

2026-11-28 D198 정정: 현재 차림 전체와의 비교는 승인된 그리기 시점 규칙과 달라 BUG-142에서 대체해요. 실제 고정된 레이어가 받은 상태·상점 상태·해시 면에서 유효한지만 확인하므로, 그리지 않은 레이어가 나중에 복구되는 것과 친구의 정상 차림 변경은 실패 사유가 아니에요. 고정된 레이어 파일 내용이 바뀐 경우는 계속 결과를 쓰지 않아요.

2026-11-28 D199 정정: 해시 기록이 없는 기존 반려동물 작업·장면은 main 방식으로 처리하고, 스위치 0의 반려동물과 일기도 기존 방식을 유지해요. 이 전의 '기록 없는 이전 장면을 쓰지 않음'은 D199로 대체해요. 해시가 기록된 새 작업만 고정 차림 검사를 해요.
