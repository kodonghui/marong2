# BUG-142 차림을 바꾸면 이미 그린 일기가 실패함

2026-11-28 PR #148 다섯 번째 리뷰에서 발견했어요. 서울 격리 환경에서 모델이 일기 그림을 그리는 동안 친구가 정상적으로 다른 차림으로 바꾸면, 시작·완료 시 차림 전체가 다르다는 이유만으로 성공 결과를 버려요. SPEC-573과 SPEC-161은 시작할 때 차림으로 그린 성공 그림을 쓰도록 해요. D198에 따라 고정 아이템 자체의 받기·상점 상태와 레이어 해시를 검사하며 이후의 정상 차림 변경은 실패가 아니에요. 원인은 11단계에서 현재 차림과 고정 차림 전체를 비교한 구현이에요.

회귀 시험: `tests/test_diary_worker.py`와 `tests/test_scene_picture.py`의 `test_bug142_`에서 밤 일기·다시 그리기·반응의 정상 차림 변경, 고정 아이템 내림·받기 취소 및 레이어 변경을 검사해요. 병합 전이므로 상태는 `open`이에요.

수정 전 `00c86da`에서 밤 일기와 다시 그리기 중 정상 차림 변경이 실패로 기록됐고, 반응에서도 다른 자리를 벗으면 성공 그림 대신 겹친 그림을 썼어요. 고정 아이템 내림·소유 해제는 반대로 놓쳤어요. `7d5672a`의 반려동물 화두·일기 시험에서도 고정 아이템을 내린 뒤 성공 그림을 쓰는 것을 재현했고, `bace05d`의 시험은 작업 대기와 시작 사이 차림 변경이 지시에 반영되지 않아 실패했어요.

`0e0d654`는 그림 작업 시작 때의 받은·상점에 올라온 유효 차림을 고정하고, 이후 차림 전체가 아니라 고정 아이템의 소유·상태와 해당 레이어 해시를 확인해요. 기본 마롱이와 반려동물의 밤 일기·다시 그리기·반응·화두 장면에서 같은 기준이며, 반응 대상 아이템을 벗거나 캐릭터가 바뀌면 종전대로 반응을 보내지 않아요. 기록이 없는 이전 장면은 고정 차림을 확인할 수 없어 재사용하지 않아요. 고정 아이템이 무효가 되면 결과를 쓰지 않고 비용은 보존해요. 서울 격리 환경에서 관련 그림·일기·프로필·선톡과 025 반복 적용을 확인했어요.

Stopped by: 고정 차림의 검증 함수를 그림 경로에서 공유하고, 현재 선택은 별도로 반응 대상의 착용 여부에만 사용해요. 타입이나 린트만으로 DB의 소유·상점 상태와 실행 중 바뀌는 실제 파일 해시를 보장할 수 없어 회귀 시험도 남겨요.
