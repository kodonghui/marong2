# BUG-143 스위치 0의 기존 그림 동작 보존

2026-11-28 PR #148 여섯 번째 리뷰에서 발견했어요. 기존 완료 장면에 해시 기록이 없거나 받은 옷을 상점에서 내리면 기본 차림 스위치 0에서도 반려동물 반응과 일기 그림을 거절해 기존 동작 및 비용이 달라져요. D193과 SPEC-575는 스위치 0의 기존 동작 보존을 요구해요. 마롱이 정정 `msg_ab491592a003`: 해시 기록이 없는 기존 작업·그림은 기존 방식으로 처리하고, 새 고정 차림 검사는 해시 기록이 있는 작업에 적용해요. 스위치 0의 반려동물·일기는 main과 같은 결과·모델 부름 수를 확인해요(작업 재사용 자체는 승인된 TASK-608).

회귀 시험: `tests/test_switch0_main_comparison.py`는 변경 전 main과 이 브랜치를 각각 임시 DB와 가짜 모델로 실행해 완료 그림 재사용·내린 옷 반응·일기 중 내림의 결과와 호출 수를 비교해요. 병합 전이므로 `open`이에요.

수정 전 `b2dd4c3`의 비교 시험에서 main은 기존 완료 장면을 쓰고 내린 옷의 일기와 반응을 정상 처리했지만 작업 브랜치는 장면을 버리고 일기 오류·반응 누락을 냈어요. `336da1c`에서는 main `0cf4e09`와 각각 임시 Postgres를 띄워 같은 합성 입력으로 결과와 비용·모델 부름 수를 비교했어요. 기존 완료 장면은 양쪽 모두 모델 0회로 재사용했고, 일기와 첫 반응은 각각 양쪽 모델 1회로 옷이 포함된 성공 결과였어요. D199는 승인된 TASK-608의 재시도 시 작업 재사용은 유지해 그 경우 중복 부름을 줄여요. 해시 없는 이전 대기·완료 반려동물 작업은 스위치 1에서도 그대로 처리하고, 스위치 1에서 새로 만든 대기 작업은 표시를 남겨 스위치 0으로 바뀌어도 작업 시작 때 해시를 기록·검사해요.

Stopped by: 스위치 0과 기록 없는 기존 작업을 기존 경로로 분리하고, 새 작업의 표시·해시가 있는 경로만 검사하는 구조와 main 비교 시험으로 막아요. 정적 타입만으로 실행 중의 스위치·이전 DB 행·모델 부름 수를 보장할 수 없어요.
