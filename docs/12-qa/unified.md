# 통합 앱(MVP): 시험 계획(12단계)

상태: 2026-11-19 11시대 KST 작성(Claude). 아직 돌리지 않았어요. 시험을 쓰고 돌리는 쪽은 GPT예요([AGENTS.md](../../AGENTS.md)). 작업은 [작업 목록](../10-wbs/unified.md)의 TASK-379\~410이에요.
입력: [기능 명세](../04-functional-spec/unified.md) SPEC-370\~396, 요구사항 REQ-430\~483, 사용자 흐름 FL-169\~178, 계약 `api/unified.openapi.yaml`(API-211\~242)과 바뀌는 계약(API-101\~107의 새 응답), 화면 정의 [08-screens/unified.md](../08-screens/unified.md) SCR-163\~174와 있는 화면에서 바뀌는 곳(그 문서 15절), 표 TBL-164\~172(`marong/migrations/020_unified.sql`), 실기기 확인 기준([설계 제안](../unified-app.md) 16절).

돌리는 법(`Runs as`):

- `unit`: 저장소의 시험 파일(`tests/test_unified_*.py`)에서 함수 하나를 불러요. 바깥 서비스와 DB가 없어요.
- `api`: 시험 파일이 앱 서버(와 통화 서버)의 HTTP 경로를 불러요. 진짜 Postgres는 `pgserver`이고 시험마다 빈 DB에 마이그레이션 020까지 적용해요. 가짜는 글·비전·그림 모델(정해 둔 답, 지연·오류·거절을 고름), Live 통화 연결, FCM(받은 요청을 모음), 쇼핑 페이지, 구글이에요. 시각은 시험 시계로 움직여요.
- `e2e`: Playwright(Chromium, 360·430px)로 화면을 열고 가짜 백엔드 위에서 상태를 만들어 봐요. 앱은 에뮬레이터(`marong_test`)의 계측 시험이에요.
- `agent`: 브라우저 에이전트(Aside, 안 되면 ego lite, 둘 다 안 되면 Playwright)가 개발 서버의 웹 페이지에서 흐름을 걸어 보고 되는 것·안 되는 것·인상을 따로 적어요(아래 '브라우저 에이전트 걷기').
- `real-model`: 진짜 모델을 불러요. 아래 '진짜 모델을 부르는 시험'의 두 가지만 허락해요.
- `server`: 반영한 서버에서 읽기 확인. `device`: 사람이 실제 폰에서 봐요(아래 '실기기 확인').

시험 데이터는 합성 데이터만 써요. 사람은 지어낸 '시험친구 가'·'시험친구 나'·'시험친구 다', 대화는 지어낸 대본, 사진은 합성 그림이나 공개 데이터셋이에요. 친구 대화 원문, 이름과 묶인 기억, 실제 사진, 실제 초대 주소·코드·토큰을 시험과 로그와 PR에 넣지 않아요. 'Data' 칸의 '기본'은 이 문단의 합성 계정 세 개를 뜻해요.
