# 마롱이 대화 저장 설계

필받음(pillboot) 채팅 저장 방식과 corthex-harness 의 기억 방식을 섞어 카카오톡 챗봇에 맞췄다.

## 가져온 것

| 출처 | 가져온 생각 | 마롱이에서 |
|---|---|---|
| 필받음 | 대화 원문 + 일정 턴마다 요약(chat_summary, 500자 안쪽) | `messages` + `summaries`(10턴마다) |
| 필받음 | 메시지·요약 임베딩으로 비슷한 예전 대화 찾기 | `embeddings` + `similar()` |
| 필받음 | 답에 넣는 기억 = 최근 원문 + 최근 요약 3개 + 비슷한 예전 대화 | 최근 10턴 + 요약 3개 + 비슷한 요약 3개·메시지 4개 |
| 필받음 | 기억·임베딩이 실패해도 답은 나감, 로그에 대화 내용 없음 | 같음 |
| corthex | 원문은 그대로 두고, 정리한 기억 항목을 따로 쌓음 | `notes`(방·친구별, 새 줄을 쌓고 최근 줄이 지금 메모) |
| corthex | 검색 색인은 원문에서 다시 만들 수 있고 어떤 모델로 만들었는지 적음 | `embeddings` 의 기본 키에 `model` |
| corthex | 표 주인(로그인 불가)과 앱 계정을 나눔 | `marong_owner` / `marong` |

## 표

- `rooms`: 카카오 `botGroupKey`. 1:1(채널채팅)도 방 하나. `proactive` 는 선톡 받기(기본 켬, 친구가 그만하라고 하면 끔. 표 버전 2). `noted_id` 는 요약을 기다리지 않고 메모를 먼저 고친 마지막 메시지(표 버전 4). `proactive_per_day`·`proactive_start`·`proactive_end` 는 그 방만의 선톡 일정(비면 `.env` 값, 표 버전 5).
- `people`: 카카오 `botUserKey` 하나와 본인이 알려 준 이름. 카카오는 이름을 주지 않고, 같은 사람도 1:1 과 단체방에서 키가 다르다. `friend_id` 로 친구 한 명에 묶인다(표 버전 3).
- `friends`: 친구 한 명(사람). 이름(가장 최근에 알려 준 것)과 `share`(가벼운 얘기를 이 친구를 아는 다른 친구에게 해도 되는지, 기본 켬).
- `friendships`: 친구가 말해 준 아는 사이와 관계(회사 동기·사촌 같은 말). 두 친구 id 중 작은 쪽이 `friend_a`.
- `shared_notes`: 친구마다 다른 친구에게 해도 되는 가벼운 얘기. 방별 메모를 걸러 새 줄로 쌓고 가장 최근 줄이 지금 것. `meta.note_ids` 에 거른 메모 id 들, `meta.rules` 에 거른 규칙.
- `messages`: 대화 원문. 쌓기만 한다. `(room_key, kakao_id)` 가 같으면 두 번 저장하지 않는다(재연결 뒤 같은 메시지가 다시 와도 한 번만 답함). `meta` 에 모델·effort·토큰 수·전달 여부, 그리고 그 답에 넣은 기억 `meta.memory`(최근 대화 구간 `recent`, 요약·메모 id, 임베딩 검색 상태 `recall`·후보 `candidates`·실제로 넣은 것 `recalled`, 아는 친구 id). 선톡은 `reply_to` 없이 `meta.proactive = true` 인 마롱이 말로 남는다(카카오 오류 코드는 `meta.send_code`, 연달아 보낸 말 수는 `meta.parts`). 사진은 '[사진] 설명'으로 남고 `meta.image` 에 종류·크기·설명에 쓴 토큰(못 열었으면 `problem`).
- `summaries`: 방마다 20개 메시지(10턴) 구간 요약. 요약에 실패한 구간은 빈 요약으로 넘긴다(다시 시도하느라 비용이 새지 않게).
- `notes`: 방 안에서 친구마다 기억할 사실(10줄 이하). 요약할 때 같이 고치고(`summary_id`), 요약 전에도 먼저 고친다(`summary_id` 비움, 아래 '메모는 바로').
- `embeddings`: 메시지·요약의 벡터. `ㅋㅋ`·`ㅇㅇ`처럼 글자가 2개 이상 이어지지 않는 말은 넣지 않는다.

## 권한(기록이 지워지지 않게)

봇 계정 `marong` 은 `rooms`·`people`·`friends`·`friendships` 만 고칠 수 있고(마지막으로 본 때·이름·선톡·공유·어느 친구인지·관계), 대화 원문·요약·메모·공유 메모·임베딩은 읽기와 쓰기(INSERT)만 된다. DELETE·UPDATE·TRUNCATE·DROP 권한이 없어서, 채팅으로 무슨 말을 해도, 프로그램에 버그가 있어도 기록이 지워지지 않는다. 지우기는 서버 관리자가 `postgres` 계정으로만 한다.

## 기억 범위

- 원문·요약·메모·검색은 모두 같은 방 안에서만 쓴다. 1:1 에서 한 얘기가 단체방에 그대로 새지 않는다.
- 방을 넘어가는 건 이름과 공유 메모(아래 '친구들')뿐이다. 공유 메모에는 취향·하는 일 같은 가벼운 얘기만 남긴다.
- 친구에게 전달되지 못한 답(`meta.delivered = false`)은 다음 대화와 요약에서 뺀다.

## 메모는 바로

요약은 20개 메시지(10턴)마다라서, 메모까지 요약을 기다리면 1:1 에서 한 얘기가 며칠씩 다른 친구에게 안 닿는다(2026-10-26: 동희가 1:1 에서 피자 좋아한다고 했는데 1:1 방이 15개뿐이라 메모가 없었고, 현경이가 자기 1:1 에서 물었을 때 몰랐음).

- 뒤 작업이 요약 다음에 `note_due` 를 돈다. 마지막 요약과 `noted_id` 뒤로 친구 말이 새로 있는 방이면, 아직 요약 안 된 대화(20개 미만)와 지금 메모를 읽혀 바뀐 친구 메모만 받는다(요약과 같은 모델·effort, 요약 지시문의 메모 규칙·지킬 것 그대로). 바뀐 메모를 쌓고 `noted_id` 를 그 구간 끝으로 옮긴다.
- 메모가 바뀌면 같은 걸음의 `share_due` 가 공유 메모를 다시 거른다. 그래서 답이 나간 뒤 몇 초 안에 다른 방 친구에게 닿는다.
- 같은 방은 1분(`NOTE_GAP_S`)에 한 번까지. 대화가 이어지는 동안 말마다 부르지 않고, 미룬 방은 그만큼 뒤에 다시 본다.
- 형식 오류·거절이면 그 구간은 넘기고, 20개가 차면 요약이 메모까지 다시 고친다.

## 단체방과 연달아 온 말

- 카카오는 단체방에서 마롱이를 태그한 메시지만 보내고 태그 글자는 뺀다(2026-10-26 확인: 단체방에서 받은 21개가 모두 태그한 말, 태그만 한 말은 빈 글). 태그 없이 한 말은 서버에 오지 않아서 코드로는 받을 수 없다. 그래서 '지금 상황'에 그렇게 알려 줘서 마롱이가 "태그 안 해도 돼"라고 하지 않게 하고, 단체방의 빈 글은 '@마롱이'(부른 것)로 받는다.
- 친구가 몇 마디를 연달아 보내면 말마다 답하지 않는다. 받은 순서대로 방마다 한 줄로 처리하면서, 답하기 전에 `REPLY_WAIT_SECONDS`(기본 2초) 기다리고, 그사이나 앞 답을 만드는 동안 같은 친구가 같은 방에 답할 말을 더 보냈으면 이 말은 저장만 한다. 마지막 말이 앞 말들까지 최근 대화로 보고 한 번에 답한다.
- 다른 친구 말과는 묶지 않는다. 이름 바꾸기·공유 설정·친구 사이 저장 같은 도구는 답하는 말을 한 친구에게 걸려서, 묶으면 앞 친구의 부탁이 다른 친구에게 걸리거나 사라진다.
- 묶어 둔 첫 말부터는 `RECENT_TURNS` 보다 길어도 최근 대화에 다 넣는다. 안 그러면 길게 이어 보낸 앞 말이 답 없이 묻힌다.

## 친구들(서로 아는 사이)

동희 친구들끼리 마롱이를 같이 아는 것처럼 하려고 표 버전 3 에서 더했다. 다른 친구 얘기는 친구끼리 편하게 할 만큼만 한다(동희님 결정, 2026-10-25).

- 키 묶기: 친구가 이름을 알려 주면(`set_name`) 같은 이름 친구에 묶는다. 같은 이름 친구가 없거나 여럿이면 새 친구로 둔다. 사람마다 1:1 방은 하나라서 1:1 키는 이미 1:1 키가 있는 친구에게 묶지 않는다(이름만 같은 다른 사람). 카카오에서 말한 적 없는 키(터미널 대화)는 묶지 않는다. 표 버전 3 전에 이름만 저장된 키는 뒤 작업이 한 번 묶는다(`link_unlinked`). 잘못 묶이면 관리자가 `admin link`·`unlink` 로 고친다.
- 아는 사이: 같은 단체방에서 말한 친구끼리, 그리고 친구가 말해 준 사이(`add_friendship`, 예: "현경이는 내 회사 동기야"). 아는 사이면 이름·관계·공유 메모를, 아니면 이름만 지금 상황에 넣는다(먼저 꺼내지 말고, 물어보면 안다고만 하고 어떻게 아는 사이인지 묻게 함). 공유를 끈 친구는 이름도 넣지 않는다.
- 공유 메모: 친구의 방별 메모(1:1·단체방)가 바뀌면 뒤 작업이 요약과 같은 모델(effort low)로 다시 거른다. 넣는 것은 음식·취미·게임·반려동물·하는 일(대략)·즐거운 계획, 빼는 것은 건강·연애·고민·감정·가족·돈·갈등·시험·면접·취업 준비·정치·종교·연락처·다른 사람 얘기·'(비밀)'. 요약할 때 친구가 비밀이라고 한 메모에 '(비밀)'을 붙이고, 공유 메모에 '비밀'·'시험'·'병원'·'이직' 같은 대표 낱말이 들어간 줄은 모델이 넣어도 코드가 한 번 더 뺀다(memory.py `SHARE_BLOCK`). 6줄, 한 줄 60자까지. 거르는 규칙(지시문·낱말)을 고치면 다음 뒤 작업 때 모든 친구를 다시 거른다(`meta.rules`).
- 친구가 "내 얘기 다른 친구한테 하지 마"라고 하면 `set_share` 로 그 친구의 공유를 끈다. 관리자는 `admin share` 로 끄고 켤 수 있다. 키를 다른 친구로 묶을 때 어느 한쪽이 공유를 껐으면 끈 쪽을 따른다.
- 다른 방의 원문·요약·메모 자체는 넣지 않는다. 선톡에도 친구 얘기는 넣지 않는다.

## 선톡(먼저 말 걸기)

- 선톡 기록을 따로 두지 않고 `messages` 에 쌓는다. 친구가 답하면 그 선톡이 보통 대화처럼 앞 문맥이 되고, 요약에도 들어간다.
- 대상: 카카오에서 온 1:1 방(`kakao_id` 가 있는 친구 말)에서 친구가 1시간(`proactive.py` `QUIET_HOURS`, 칸이 짧으면 칸 반 길이) 넘게 조용하고(이야기 중이면 안 끼어듦) 이번 칸에 선톡이 없는 방. 지난 선톡에 답이 없어도 보낸다. 2026-10-25 동희님 결정으로 '사흘 조용하면 한 번' → '이틀에 한 번쯤'("이틀에 하루정도는 선톡 주게 해줘") → '하루에 두어 번, 답이 없어도'("내가 먼저 안보내도 그냥 보내라고 하루에 두어번 보내")로 바꿨다.
- 칸: 방의 일정 시간을 하루 횟수만큼 칸으로 똑같이 나눈다. 기본은 `PROACTIVE_HOURS`(12~21시)를 `PROACTIVE_PER_DAY`(2) 칸으로(12:00~16:30, 16:30~21:00). 한국 시각 매분 확인하고, 칸에 남은 확인 횟수가 n 이면 1/n 확률로 보내서 보내는 시각이 칸 안에 고루 퍼지고 칸 마지막 확인에선 꼭 보낸다. 칸 경계에서 연달아 가지 않게 지난 선톡에서 칸 반 길이가 지나야 한다. 한 번 확인할 때 대상 친구 모두에게 보낸다(한 명씩이면 칸 마지막 확인에서 둘째 친구가 빠짐). 하루 상한 `PROACTIVE_DAILY_MAX`(기본 30)는 모든 친구 합.
- 방마다 일정: `rooms.proactive_per_day`·`proactive_start`·`proactive_end` 가 있으면 `.env` 값 대신 쓴다(관리자 `admin schedule`, 친구가 횟수를 바꿔 달라고 하면 `set_proactive` 의 `per_day`). 2026-10-26 동희님 "07시부터 24시까지 랜덤으로 하루에 10번 이상 선톡시켜 현경이한테" → 현경이 방은 7~24시 12번(85분 칸). 1시간 조용해야 한다는 조건을 그대로 두면 짧은 칸에서는 이야기가 이어질 때 칸을 통째로 건너뛰어서, 칸이 짧으면 칸 반 길이(85분 칸이면 42분 30초)로 줄인다.
- 여러 말: 2026-10-26 동희님 "한번 말 걸 때 여러개 말 걸어주라고 해줘" → 짧은 말 2~3개(빈 줄로 나눔, 많아야 4개)를 2~6초 간격으로 전송 API 를 따로 불러 보낸다. 기록은 묶음 하나(마롱이 말 한 줄, 하루 상한도 한 번)로 남기고, 중간에 끊기면 친구가 받은 말까지만 남긴다.
- 시각 조건(조용한 시간·이번 칸·오늘 보낸 수)은 DB 시계 `now()` 에서 거꾸로 잰 길이로 넘긴다(시험에서 시계를 마음대로 정할 수 있게).
- 전달에 실패한 선톡도 남겨서 같은 칸에 다시 시도하지 않는다(첫 말부터 실패하면 만든 말 전부를 전달 안 됨으로). 친구가 마지막으로 말한 뒤로 전달 실패가 두 번이면(차단 등) 친구가 다시 말할 때까지 뺀다.
- 선톡을 만들 때는 그 방의 최근 원문·요약·메모만 읽는다(다른 방 기억은 안 섞임). 도구 없이 한 번 부르고, 오류·거절·빈 답이면 보내지 않는다.
- 같은 방의 답장과 선톡은 한 잠금으로 줄을 세운다. 선톡을 만드는 동안 친구가 말하면 선톡을 보낸 뒤에 답하고, 잠금을 얻은 뒤 대상인지 다시 확인한다.
- 카카오 전송 API 는 1:1 이면 `botUserKey` 로 보낸다. 다시 보내면 두 번 갈 수 있어서 실패해도 다시 보내지 않는다.

## 사진

2026-10-26 동희님 "사진 인식도 좀 하면좋겠는데".

- 카카오는 사진 메시지를 서명된 카카오 CDN 주소 하나(`https://talk.kakaocdn.net/…?credential=…&expires=…&signature=…`)로 보낸다. 주소 안에 인증값이 있어서 저장·로그에 남기지 않는다.
- 주소가 곧 만료돼서 방 차례를 기다리지 않고 받자마자 내려받기 시작하고, 답은 방 잠금 안에서 받은 순서대로 한다. 카카오 CDN 밖으로 옮기는 주소는 따라가지 않고(두 번까지), 3.75MB(Claude 사진 한 장 5MB 를 base64 로)까지, 종류는 파일 앞부분으로 정한다(jpeg·png·gif·webp).
- 기록은 고칠 수 없어서(INSERT 만) 저장하기 전에 Claude 에게 사진을 보여 주고 짧은 설명(effort low, 200자 안쪽)을 받아 '[사진] 설명'으로 저장한다. 그 사진에 답할 때는 사진 자체를 보여 주고(뒤에 이어 온 말과 묶어 답할 때도), 답한 뒤에는 설명으로만 기억한다. 사진은 디스크에 두지 않는다.

## 기록 리포트(엑셀·구글 시트)

- 2026-10-26 동희님 "30m에 한번씩 스프레드시트에 업로드해주는걸로 바꿀수있나? 대화내용 임베딩된 내역 그게 언제 어떻게 먹여졌는지" → 서버 systemd 타이머(`marong-sheet.timer`)가 30분마다 `tools/report.py --sheet` 를 돌려 최근 30일(`SHEET_DAYS`) 기록을 구글 시트 웹 앱(`tools/sheet.gs`)으로 보내고, 웹 앱이 탭마다 지우고 다시 쓴다. 노트북이 꺼져 있어도 된다.
- '들어간 기억' 탭은 답마다 `meta.memory` 를 펼친 것이다. 그 기록을 남기기 전에 보낸 답은 '기록 전'으로 보인다.
- 웹 앱 주소(`SHEET_URL`)는 아는 사람이 시트에 쓸 수 있는 비밀이라 서버 `.env` 에만 두고, 출력·로그에 남기지 않는다(httpx INFO 로그도 끔). 웹 앱은 쓰기(`doPost`)만 있고 읽기는 없다. 시트에는 벡터 앞 8개 값만 보내고 벡터 전체는 엑셀(`ovh.sh report`)에만 둔다.

## 임베딩

- `google/embeddinggemma-300m`(768차원)을 fastembed(ONNX)로 서버 CPU 에서 계산한다. 대화 원문을 임베딩 회사 API 로 보내지 않는다.
- 한국어 시험(예전 말 10개, "내 생일 알아?" 같은 질문 7개)에서 7개 모두 맞는 예전 말을 1등으로 찾아서 골랐다. 모델 카드가 권하는 접두어(`task: search result | query: `, `title: none | text: `)를 붙인다.
- 비슷함 0.4 미만은 넣지 않는다(`RECALL_MIN_SIMILARITY`).
- 데이터가 작아서 정확 검색(색인 없이 코사인 거리)을 쓴다. 방 하나에 수십만 개가 넘으면 HNSW 색인을 더한다.
- 모델을 바꾸면 새 모델 이름으로 새로 쌓인다. 옛 모델 줄은 관리자가 지워도 된다(원문에서 다시 만들 수 있음).

## 실패할 때

| 고장 | 마롱이 |
|---|---|
| Postgres 가 꺼짐 | 5초 기다린 뒤 기억 없이 답함. 그 대화는 저장되지 않음 |
| 임베딩 모델이 아직 준비 안 됨 | 비슷한 예전 대화 없이 답함. 준비되면 밀린 것을 임베딩 |
| Claude 주 키 실패 | 백업 키로 한 번 더. 둘 다 실패하면 대체 문구 |
| Claude 가 거절 | "다른 얘기 하자" 문구 |
| 답이 글 없이 끝남(xhigh 에서 가끔) | system 메시지로 한 번 더 쓰게 함 |
| 콜백 토큰(5분)이 얼마 안 남음 | Claude 를 부르지 않고 다시 말해 달라고 함 |
| 요약 실패 | 쉬었다가 다시. 형식 오류가 2번 이어지거나 거절이면 빈 요약으로 넘김 |
| 친구들을 못 모음(쿼리 오류) | 다른 친구 얘기 없이 이 방 기억으로 답함 |
| 공유 메모 거르기 실패 | 쉬었다가 다시. 형식 오류가 2번 이어지거나 거절이면 빈 공유 메모(다른 친구에게 할 얘기 없음) |
| 이름이 같은 다른 사람이 한 친구로 묶임 | `admin unlink <#키>` 로 떼어 냄 |
| 같은 사람이 방마다 다른 이름을 알려 줌 | `admin link <#키> <친구>` 로 묶음 |
| 선톡 말을 못 만듦(오류·거절·빈 답) | 보내지 않고 그 방은 그 칸엔 건너뜀 |
| 선톡 전송 실패(-877 채널 친구 아님, -879 알림 끔, -880 초대 안 됨 등) | 전달 안 됨으로 남기고 그 칸엔 다시 안 보냄. 친구가 말한 뒤로 두 번이면 친구가 말할 때까지 쉼 |
| 선톡을 연달아 보내다 끊김 | 거기서 멈추고 친구가 받은 말까지만 남김 |
| 사진이 너무 큼·사진이 아님·안 열림 | '[사진] (못 열었어)'로 남기고 다시 보내 달라고 답함 |
| 사진 설명을 못 받음(오류·거절) | '[사진] (설명을 못 남겼어)'로 남기고, 답할 때는 사진을 그대로 보여 줌 |
| 구글 시트로 못 보냄 | 그번은 건너뛰고 30분 뒤 다시(`sheet status` 에 까닭만, 주소는 안 남김) |
